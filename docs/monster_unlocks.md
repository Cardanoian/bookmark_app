# 「책갈피」 몬스터 해금 규칙 설계서

> 상태: **구현 완료**. 이 문서는 몬스터 24개 라인의 1단계 폼을 얻는 규칙을 정의한다.
> `MonsterUnlock` 서비스(`app/services/monster_unlock.rb`)·`MonsterSpecies#unlock_condition` 컬럼(`app/models/monster_species.rb`)·`db/seeds/monsters.yml`의 24라인 `unlock_condition`·`rails monsters:backfill_unlocks` 백필 태스크(`lib/tasks/monsters.rake`)·`monsters#index`/`#show` 조회 시 self-heal 재평가까지 전부 배포되어 있다.

## 1. 목표와 기본 원칙

- 해금은 몬스터 **라인의 1단계 폼을 처음 얻는 것**이다. 이후 2·3단계 진화 조건과는 별개다.
- 포인트로 몬스터를 구매하지 않는다. 독서·게임·미션 활동 조건을 달성하면 자동으로 얻는다.
- 모든 조건은 누적 기록으로 판정한다. 여러 조건이 적힌 레어·에픽 몬스터는 **모두 충족(AND)**해야 한다.
- 같은 라인은 학생당 한 번만 지급한다. 이미 보유한 스타터나 몬스터는 중복 지급하지 않는다.
- 한 번 얻은 몬스터는 첨삭 등급 수정 등으로 수치가 낮아져도 회수하지 않는다.
- 가챠·확률·유료 해금은 사용하지 않는다. 같은 활동 기록에는 항상 같은 결과가 나와야 한다.
- 잠긴 도감 카드에는 조건과 현재 진행도(예: `승인 독후감 4/6편`)를 공개한다.

### 레어도별 난이도

| 레어도       | 조건 구성              | 목표 시점        | 품질 조건 사용                          |
| ------------ | ---------------------- | ---------------- | --------------------------------------- |
| 일반(common) | 쉬운 단일 조건 1개     | 첫 활동부터 초반 | A등급을 요구하지 않음                   |
| 레어(rare)   | 서로 보완하는 조건 2개 | 중기             | A등급을 포함할 수 있으나 단독 사용 금지 |
| 에픽(epic)   | 장기 조건 3개 이상     | 장기·도감 후반   | A등급과 폭넓은 활동을 함께 요구         |

레어·에픽의 A등급 조건은 단순 경쟁을 위한 것이 아니라, 충분한 참여량 뒤에 글의 완성도까지 도전하게 하는 심화 조건이다. 저학년이나 평가 방식 차이로 인한 불이익을 줄이기 위해 A등급 하나만으로 해금되는 몬스터는 두지 않는다.

## 2. 해금 조건 키 사전

현재 24개 라인은 모두 수치 조건을 쓰며, 수치 값은 음이 아닌 정수이고 `현재값 >= 목표값`으로 판정한다. 공용 조건 문법에는 뱃지 보유 여부를 확인하는 `badge`도 포함되지만, 현재 24개 라인의 `unlock_condition`에는 사용하지 않는다.

| ------------------- | ---------------- | ---------------------------------------------------------------- | ------------------- |

### 일일 독후감 판정 규칙

- `max_daily_reports`는 앱 시간대(`Asia/Seoul`)의 제출일을 기준으로 묶는다.
- 교사가 최종 승인한 독후감만 세며, 연결된 `Book.title` 또는 정규화한 `book_title`로 책을 구분한다. 같은 책의 독후감을 같은 날이나 다른 날에 여러 편 제출해도 전체 기간 중 가장 먼저 작성한 한 편만 인정한다.
- 목표는 “매일 여러 편”이 아니라 **과거 어느 하루에 목표 편수를 달성했는가**다.
- 초등학생의 속도 경쟁과 저품질 제출을 막기 위해 해금 임계값은 일반 2편, 레어 최대 3편까지만 사용한다.

### 게임 판정 규칙

게임 종류는 학생 게임 카탈로그의 활성 4종을 기준으로 한다(게임 재구성으로 `vocab`은 삭제, `classic`은 폐기[표면 제거, 과거 기록만 값으로 보존]되었고 `sequel`이 새로 추가되었다).

1. 독서 퀴즈(`quiz`)
2. 나는 누구게?(`whoami`)
3. 책 소개 대결(`book`)
4. 뒷이야기 이어쓰기(`sequel`)

`game_plays`는 단순 페이지 진입이 아니라 답안 제출 또는 책 소개·뒷이야기 등록까지 끝낸 **완료 기록**만 센다. 반복 새로고침·재제출 파밍을 막기 위해 같은 학생이 같은 날 같은 책으로 같은 게임을 여러 번 완료해도 한 번만 인정한다. 책이 없는 완료 기록도 같은 학생·게임·날짜당 한 번만 인정한다. 다른 게임으로 같은 책을 플레이하면 게임별로 각각 한 번 인정한다.

`distinct_games`는 위 4개 활성 게임 종류의 distinct 수다. 다만 표면에서 제거된 `classic`의 과거 원장 기록은 보존되며 이 지표에도 포함된다. `game_books`는 게임 종류와 관계없이 유효 완료 기록에 연결된 `book_id`의 distinct 수다. 책이 연결되지 않은 교사 제작 퀴즈는 `game_plays`와 `distinct_games`에는 포함할 수 있지만 `game_books`에는 포함하지 않는다.

`game_plays` 활동 원장(`GamePlay` 모델, `app/models/game_play.rb`)이 게임 완료를 영속화하고, `ReadingStats#game_plays`/`#distinct_games`/`#game_books`가 이를 집계 소스로 쓴다. `book`·`sequel`은 라우트가 `game_type`을 확정하지만, 퀴즈 표면(`quiz`·`whoami`)은 `Quiz` 행만으로 표면을 권위적으로 구분할 수 없어 허용 목록 내 `params[:game]` 선언을 기록한다. 즉, 퀴즈 표면의 유형은 서버 결정값이 아니라 검증된 클라이언트 선언이며, 이 편차로 학생이 얻을 수 있는 이득은 `distinct_games`를 빨리 채우는 것뿐이다.

## 3. 24종 전체 해금 조건

## 4. 자동 지급 흐름

1. `MonsterUnlock#evaluate!`는 `stage: 1`이면서 `unlock_condition`이 있는 라인만 dex 번호순으로 후보로 잡는다.
2. 각 라운드에서 최신 `ReadingStats`와 보유 dex 번호를 새로 읽고, 미보유 후보의 모든 조건을 AND로 평가한다.
3. 충족한 라인은 `MonsterAcquisition#discover_monster!`로 1단계 폼을 생성한다. 이미 보유한 라인은 건너뛴다.
4. 새로 생성한 라인이 있으면 다시 평가한다. `dex_count`처럼 방금 지급한 라인 수에 의존하는 조건도 같은 `evaluate!` 호출에서 이어서 해금되며, 최대 24라운드 후에는 반드시 끝난다.
5. 반환값은 이번 호출에서 생성한 `UserMonster` 목록이다. 개별 지급 실패는 로그만 남기고 다른 후보의 평가를 계속한다.

새 `UserMonster`는 `celebrated_at`이 비어 있는 상태로 만들어진다. 레이아웃은 이를 `obtained_at` 순으로 발견 모달에 넣고, 학생이 확인하면 `celebrated_at`을 기록해 재노출을 막는다. 따라서 서비스가 별도의 발견 이벤트나 알림 큐를 만들지는 않는다.

평가가 필요한 주요 시점은 다음과 같다.

- 교사가 독후감을 승인하거나 검토 내용을 저장한 뒤
- 퀴즈·나는 누구게?·책 소개 대결·뒷이야기 이어쓰기에서 **새** `GamePlay` 완료 기록이 생긴 뒤
- 토론 글이 생성된 뒤
- 스타터 선택 직후와 기존 학생 대상 배치 재평가 시
- 도감 목록·상세를 열 때(쓰기 트리거를 놓친 조건 충족분을 보정하는 self-heal)

`(user_id, dex_no)` 유니크 제약이 중복 지급의 최종 방어선이다. 서비스도 지급 전에 보유 여부를 확인하며, 동시 요청으로 발생한 `RecordNotUnique`를 포함한 개별 지급 오류는 해당 라인만 건너뛰고 로그로 남긴다. 서비스 자체에는 트랜잭션 재시도나 별도 발견 이벤트 멱등 키가 없다.

## 5. 구현 데이터 계약

몬스터 라인 단위로 다음과 같은 데이터를 두는 방식을 권장한다.

```yaml
- dex_no: 7
  element: knowledge
  rarity: rare
  unlock_condition:
    game_plays: 8
    distinct_games: 3
```

- `unlock_condition`은 라인에 속하며 1단계·2단계·3단계 폼마다 반복 저장하지 않는다.
- 기존 `evolve_condition`과 같은 조건 해시 문법을 사용하되 두 개념을 혼용하지 않는다.
- 지원 키는 화이트리스트로 검증하고, 알 수 없는 키나 음수 목표값은 시드·관리자 저장 단계에서 거부한다.
- 조건 설명 문구는 자유 텍스트로 중복 저장하지 않고 키와 목표값으로 생성한다.
- 기존 학생에게 기능을 배포할 때는 `rails monsters:backfill_unlocks`로 전체 조건을 한 번 재평가한다. 여러 몬스터가 한꺼번에 지급되어도 각 `UserMonster`의 미확인 상태를 레이아웃의 발견 모달이 다음 페이지 로드에서 드레인한다.

## 6. 밸런스 점검 기준

출시 후 학년군별 실제 데이터를 보고 임계값을 조정한다. 첫 점검에서는 다음 지표를 본다.

- 가입 후 첫 자동 몬스터 획득까지 걸린 중앙값
- 30일 안에 획득한 일반·레어 몬스터 수
- 특정 몬스터의 학년별 해금률 차이
- A등급 조건 몬스터의 학년·학급별 편차
- `max_daily_reports` 도입 후 같은 날 저품질·중복 제출 증가 여부
- 동일 게임·동일 책 반복 플레이 비율
- 6개 속성 중 사실상 진행되지 않는 활동 축 존재 여부

목표는 초반에 스타터 외 2~4종을 자연스럽게 만나고, 레어는 꾸준한 활동으로, 에픽은 장기 목표로 남는 분포다. A등급이나 하루 작성량이 낮은 학생도 일반 몬스터와 다른 활동 축을 통해 도감을 계속 채울 수 있어야 한다.
