# 「책갈피」 몬스터 해금 규칙 설계서

> 상태: **구현 예정 설계**. 이 문서는 몬스터 24개 라인의 1단계 폼을 얻는 규칙을 정의한다.
> 현재 앱에는 스타터 선택과 `MonsterAcquisition#discover_monster!`만 있으며, 아래 조건 판정과 자동 지급 훅은 아직 연결되어 있지 않다.

## 1. 목표와 기본 원칙

- 해금은 몬스터 **라인의 1단계 폼을 처음 얻는 것**이다. 이후 2·3단계 진화 조건과는 별개다.
- 포인트로 몬스터를 구매하지 않는다. 독서·게임·미션 활동 조건을 달성하면 자동으로 얻는다.
- 모든 조건은 누적 기록으로 판정한다. 여러 조건이 적힌 레어·에픽 몬스터는 **모두 충족(AND)**해야 한다.
- 같은 라인은 학생당 한 번만 지급한다. 이미 보유한 스타터나 몬스터는 중복 지급하지 않는다.
- 한 번 얻은 몬스터는 첨삭 등급 수정 등으로 수치가 낮아져도 회수하지 않는다.
- 가챠·확률·유료 해금은 사용하지 않는다. 같은 활동 기록에는 항상 같은 결과가 나와야 한다.
- 잠긴 도감 카드에는 조건과 현재 진행도(예: `승인 독후감 4/6편`)를 공개한다.

### 레어도별 난이도

| 레어도       | 조건 구성              | 목표 시점        | 품질 조건 사용                          |
| ------------ | ---------------------- | ---------------- | --------------------------------------- |
| 일반(common) | 쉬운 단일 조건 1개     | 첫 활동부터 초반 | A등급을 요구하지 않음                   |
| 레어(rare)   | 서로 보완하는 조건 2개 | 중기             | A등급을 포함할 수 있으나 단독 사용 금지 |
| 에픽(epic)   | 장기 조건 3개 이상     | 장기·도감 후반   | A등급과 폭넓은 활동을 함께 요구         |

레어·에픽의 A등급 조건은 단순 경쟁을 위한 것이 아니라, 충분한 참여량 뒤에 글의 완성도까지 도전하게 하는 심화 조건이다. 저학년이나 평가 방식 차이로 인한 불이익을 줄이기 위해 A등급 하나만으로 해금되는 몬스터는 두지 않는다.

## 2. 해금 조건 키 사전

조건 값은 모두 음이 아닌 정수이며 `현재값 >= 목표값`으로 판정한다.

| 키                  | 화면 표시        | 판정 기준                                                        | 현재 구현           |
| ------------------- | ---------------- | ---------------------------------------------------------------- | ------------------- |
| `reports`           | 승인 독후감      | 교사가 승인한 독후감 누적 편수                                   | 있음                |
| `max_daily_reports` | 하루 최다 독후감 | 하루에 제출한 **서로 다른 책의 승인 독후감** 편수 중 역대 최댓값 | 추가 필요           |
| `distinct_genres`   | 읽은 장르        | 승인 독후감과 연결된 서로 다른 도서 카테고리 수                  | 있음                |
| `a_grades`          | A등급 독후감     | 교사가 승인했고 최종 첨삭 등급이 A인 독후감 수                   | 있음                |
| `b_or_better`       | B등급 이상       | 교사가 승인했고 최종 첨삭 등급이 A 또는 B인 독후감 수            | 있음                |
| `classics`          | 고전 읽기        | 고전 카테고리의 서로 다른 책에 연결된 승인 독후감 수             | 중복 방지 보완 필요 |
| `revisions`         | 향상된 고쳐쓰기  | 승인 독후감 중 고쳐쓰기 향상도가 0보다 큰 편수                   | 있음                |
| `streak_days`       | 최장 연속 독서   | 독후감 제출일 기준 최장 연속 달력일 수                           | 있음                |
| `missions`          | 참여 미션        | 독후감으로 참여한 서로 다른 미션 수                              | 있음                |
| `challenges`        | 참여 챌린지      | 독후감으로 참여한 서로 다른 챌린지 수                            | 있음                |
| `topic_posts`       | 토론 글          | 학생이 작성한 토론 글 수                                         | 있음                |
| `game_plays`        | 게임 플레이      | 유효한 게임 완료 기록 누적 횟수                                  | 추가 필요           |
| `distinct_games`    | 서로 다른 게임   | 플레이한 게임 종류 수. 최대 5종                                  | 추가 필요           |
| `game_books`        | 게임으로 만난 책 | 유효한 게임을 플레이한 서로 다른 책 수                           | 추가 필요           |
| `dex_count`         | 보유 몬스터      | 보유한 서로 다른 몬스터 라인 수                                  | 있음                |

### 일일 독후감 판정 규칙

- `max_daily_reports`는 앱 시간대(`Asia/Seoul`)의 제출일을 기준으로 묶는다.
- 교사가 최종 승인한 독후감만 세며, `book_id`가 없거나 같은 책으로 같은 날 여러 편을 제출한 경우 한 편만 센다.
- 목표는 “매일 여러 편”이 아니라 **과거 어느 하루에 목표 편수를 달성했는가**다.
- 초등학생의 속도 경쟁과 저품질 제출을 막기 위해 해금 임계값은 일반 2편, 레어 최대 3편까지만 사용한다.

### 게임 판정 규칙

게임 종류는 학생 게임 카탈로그의 5종을 기준으로 한다.

1. 독서 퀴즈(`quiz`)
2. 고전 읽기 여행(`classic`)
3. 어휘 낚시(`vocab`)
4. 나는 누구게?(`whoami`)
5. 책 소개 대결(`book`)

`game_plays`는 단순 페이지 진입이 아니라 답안 제출 또는 책 소개 등록까지 끝낸 **완료 기록**만 센다. 반복 새로고침·재제출 파밍을 막기 위해 같은 학생이 같은 날 같은 책으로 같은 게임을 여러 번 완료해도 한 번만 인정한다. 다른 게임으로 같은 책을 플레이하면 게임별로 각각 한 번 인정한다.

`distinct_games`는 위 5개 게임 종류의 distinct 수다. `game_books`는 게임 종류와 관계없이 유효 완료 기록에 연결된 `book_id`의 distinct 수다. 책이 연결되지 않은 교사 제작 퀴즈는 `game_plays`와 `distinct_games`에는 포함할 수 있지만 `game_books`에는 포함하지 않는다.

현재 `quiz_attempts`에는 실제 진입 표면이 저장되지 않아 같은 `mcq` 콘텐츠를 공유하는 `quiz`와 `classic`을 구분할 수 없다. 구현 시 클라이언트 파라미터를 그대로 신뢰하지 말고 서버가 결정한 게임 종류를 영속화해야 한다. 네 가지 퀴즈형 게임의 완료와 `BookIntro` 생성을 같은 방식으로 집계할 수 있도록 `game_plays` 활동 원장 또는 이에 준하는 서버 권위 기록을 두는 것을 권장한다.

## 4. 자동 지급 흐름

1. 관련 활동이 확정되면 학생의 최신 통계를 계산한다.
2. 아직 보유하지 않은 라인의 해금 조건만 평가한다.
3. 조건을 모두 만족한 라인은 `MonsterAcquisition#discover_monster!`로 1단계 폼을 생성한다.
4. 동시에 여러 조건을 만족하면 해당 몬스터를 모두 지급하고 발견 연출은 순서대로 보여 준다.
5. 도감 카드, 도감 완성도, 대표 몬스터 선택 목록과 관련 뱃지를 즉시 갱신한다.

평가가 필요한 주요 시점은 다음과 같다.

- 교사가 독후감을 승인하거나 최종 등급을 변경한 뒤
- 게임 완료 기록 또는 책 소개 대결 글이 생성된 뒤
- 미션·챌린지 참여 독후감이 승인된 뒤
- 토론 글이 생성된 뒤
- 스타터 선택 직후와 기존 학생 대상 배치 재평가 시

자동 지급은 트랜잭션 재시도나 중복 이벤트에도 안전해야 한다. `(user_id, dex_no)` 유니크 제약을 최종 방어선으로 사용하고, 발견 연출 이벤트도 별도 멱등 키를 가져야 한다.

## 5. 구현 데이터 계약

몬스터 라인 단위로 다음과 같은 데이터를 두는 방식을 권장한다.

```yaml
- dex_no: 7
  element: knowledge
  rarity: rare
  unlock_condition:
    game_plays: 8
    distinct_games: 3
```

- `unlock_condition`은 라인에 속하며 1단계·2단계·3단계 폼마다 반복 저장하지 않는다.
- 기존 `evolve_condition`과 같은 조건 해시 문법을 사용하되 두 개념을 혼용하지 않는다.
- 지원 키는 화이트리스트로 검증하고, 알 수 없는 키나 음수 목표값은 시드·관리자 저장 단계에서 거부한다.
- 조건 설명 문구는 자유 텍스트로 중복 저장하지 않고 키와 목표값으로 생성한다.
- 기존 학생에게 기능을 배포할 때는 전체 조건을 한 번 재평가한다. 여러 몬스터가 한꺼번에 지급될 수 있으므로 배치 처리와 발견 알림 큐를 준비한다.

## 6. 밸런스 점검 기준

출시 후 학년군별 실제 데이터를 보고 임계값을 조정한다. 첫 점검에서는 다음 지표를 본다.

- 가입 후 첫 자동 몬스터 획득까지 걸린 중앙값
- 30일 안에 획득한 일반·레어 몬스터 수
