# AI 첨삭 모델 선정 근거 — `gemini-3.5-flash-lite`

'책갈피'의 AI 기능(5축 발전적 첨삭·손글씨 OCR·독서게임 문항 생성·진위 확인·줄거리 생성·뒷이야기 격려 코멘트)은
Google Gemini 를 통해 동작한다. 이 문서는 **여러 Gemini 후보 모델을 실제 5축 첨삭으로 비교한 뒤
`gemini-3.5-flash-lite` 를 선정한 근거**를 기록한다.

> 모델은 `app/services/ai/gemini_client.rb` 의 `MODEL` 상수 한 곳에서만 지정되며(단일 진실원),
> 모든 AI 기능이 이 값을 공유한다.

- 기준일: 2026-07 (가격·모델 라인업은 이 시점 공식 문서 기준)
- 평가 방법: 아래 [평가 방법](#평가-방법) 참고 (독후감 6편 × 5축 첨삭 실제 API 호출)

---

## 1. 결론

**`gemini-3.5-flash-lite` 를 선정한다.** 이유를 한 줄로 요약하면,

> "모든 후보가 학년 눈높이·성취기준을 안전하게 지키는 상황에서,
> **가장 저렴하고(라이트 티어) 그중 가장 최신 세대**인 모델이기 때문"이다.

- 상위 티어(풀 플래시·프로)는 품질이 미세하게 좋지만 **비용 10~22배·지연 4~10배**로, 짧은 초등 독후감 첨삭에는 과잉이다.
- 더 싼 `gemini-3.1-flash-lite`도 있으나 **구세대**다. 3.5-flash-lite 는 1,000건당 약 $0.33 더 비쌀 뿐(사실상 무시 가능)이면서 **최신 세대**라 지시 준수·안전성·지원 수명에서 낫다.
- 앱은 **규칙기반 첨삭 폴백 + JSON 스키마 검증**을 갖춰, 라이트 모델의 품질 리스크가 이미 완충되어 있다.

## 3. 평가 방법

- **과제**: 실제 프로덕션 경로와 동일하게, 학년군별 `ReadingDomain.rubric_prompt(band)` 를 system_instruction 으로
  주입하고 `responseMimeType: application/json` 으로 5축 첨삭 JSON 을 생성.
- **표본**: 각 학년군 눈높이로 쓴 학생 독후감 **6편**.
  - 1~2학년군(g12): 『구름빵』, 『강아지똥』
  - 3~4학년군(g34): 『마당을 나온 암탉』, 『샬롯의 거미줄』
  - 5~6학년군(g56): 『처음 읽는 삼국지』, 『몽실 언니』
- **모델 수**: 후보 6종.
- **측정**: (1) 학년군 성취기준 준수(허용 목록 밖 코드 인용 여부), (2) 지연시간, (3) 입력/출력/thinking 토큰,
  (4) 등급·루브릭, (5) 첨삭 문체 품질.
- **총 36회 호출**(6 모델 × 6 독후감).

---

## 4. 결과

### 4.1 학년군 성취기준 안전성 — **전 모델 통과 (36/36 위반 0)**

가장 중요한 안전 기준이다. 과거 "3학년 독후감에 6학년 성취기준을 제시하며 수정 요구" 문제가 있었고,
이를 프롬프트의 **학년군 성취기준 allowlist + 상위 학년 요구 금지 하드 제약**으로 차단했다
(`ReadingDomain::CURRICULUM_STANDARDS_BY_BAND`, `build_rubric_prompt`).

측정 결과, **6개 후보 전부가 6편 × 3개 학년군 모두에서 자기 학년군 코드(2국/4국/6국)만 인용**했고,
상위·타 학년군 성취기준이나 상위 수준 요구가 새어 나온 경우는 **한 건도 없었다.**

→ **학년 안전성은 모델 간 변별 요소가 아니다**(모두 안전). 따라서 선택은 **비용·속도·품질의 균형**으로 귀결된다.

### 4.2 비용·속도 (측정값, 6편 평균)

| 모델                        | 평균 지연 | 평균 출력+thinking 토큰 | **추정 비용 / 1,000건** | 비고                 |
| --------------------------- | --------: | ----------------------: | ----------------------: | -------------------- |
| `gemini-3.1-flash-lite`     |     1.95s |                     362 |               **$0.91** | 최저가·구세대        |
| **`gemini-3.5-flash-lite`** | **2.03s** |                 **320** |               **$1.24** | **선정**             |
| `gemini-2.5-flash`          |     15.1s |                   3,011 |                   $7.97 | 구세대·thinking 과다 |
| `gemini-3.6-flash`          |     7.55s |                   1,411 |                  $12.77 | 최신 풀플래시        |
| `gemini-3.5-flash`          |     8.57s |                   1,814 |                  $18.52 | 풀플래시             |
| `gemini-3.1-pro-preview`    |     21.2s |                   2,009 |                  $27.03 | 플래그십·과잉        |

- 입력 토큰 평균 ≈ 1,461개(약 1,200토큰 시스템 프롬프트 + 독후감 본문).
- 비용 = 입력×입력요율 + (출력+thinking)×출력요율. thinking 은 출력 요율로 과금.
- 라이트 2종은 thinking 토큰이 0이라 지연·비용이 압도적으로 낮다. 반대로 `2.5-flash` 는 요율은 라이트급이지만
  첨삭 1건에 thinking 토큰을 평균 3,000개 태워 **가성비가 가장 나쁘다.**

### 4.3 품질 특성 (문체·유용성)

모든 모델이 잘 쓴 표본 6편에 대해 **동일하게 A 등급**을 주었고, 루브릭은 미세 차이만 있었다. 문체 차이는 다음과 같다.

| 모델                                    | 첨삭 문체 특성                                                                            |
| --------------------------------------- | ----------------------------------------------------------------------------------------- |
| `gemini-3.1-pro-preview`                | 추론·정밀도 최고. 맞춤법 미세 교정까지 잡아냄. 다만 짧은 초등 독후감엔 **과잉**(21s·$27). |
| `gemini-3.6-flash` / `gemini-3.5-flash` | 풍부하고 따뜻한 풀플래시 품질. 제안이 구체적. 8~9s·$12~18.                                |
| **`gemini-3.5-flash-lite`**             | **간결·정확하며 항상 학년 눈높이에 맞음.** 강한 글엔 보완을 압축. 2s·$1.24.               |
| `gemini-3.1-flash-lite`                 | 3.5-lite 와 대등(때때로 더 장황). 최저가지만 **구세대**.                                  |
| `gemini-2.5-flash`                      | 구세대. 칭찬을 5개씩 다는 등 장황(1~2학년엔 과함), 느림(15s).                             |

→ 상위 티어의 품질 우위는 **한계적**이다. 초등 5축 첨삭이라는 과제 특성상 라이트 모델의 품질로 충분하며,
   출력은 여러 신호 중 하나이고 규칙기반 폴백이 뒤를 받친다.

### 4.4 OCR 교차 검증 (선정 모델)

모델은 첨삭 외 손글씨 OCR 등도 공유하므로, 실제 손글씨 독후감 2건(『강아지똥』·『피그말리온』)으로 `gemini-3.5-flash-lite` OCR 을 스모크 테스트했다 — **인식 정확도는 구세대 2.5-flash 와 대등**(고유명사·문단 구조 보존, 그림·배어나온 글자·줄번호 등 노이즈 무시)하고 **속도는 2~3배 빠름**(2.5s·4.4s)으로 문제없이 동작했다.

## 5. 선정 근거 — 왜 `gemini-3.5-flash-lite` 인가

### 5.1 왜 라이트 티어인가 (vs 풀 플래시 / 프로)

- 모든 티어가 **학년 안전성 통과**, 등급도 동일. 상위 티어의 품질 이득은 문체 풍부함 정도로 **한계적**.
- 대신 상위 티어는 **비용 10~22배·지연 4~10배**. 학교 현장에서 대량 첨삭 시 비용·응답성 부담이 크다.
- 앱은 **규칙기반 첨삭 폴백 + JSON 스키마 검증 + 신고/재생성 안전망**을 이미 갖춰, 라이트 모델의 리스크가 완충됨.

### 5.2 왜 3.5-flash-lite 인가 (vs 더 싼 3.1-flash-lite)

- `gemini-3.1-flash-lite` 가 1,000건당 약 $0.33 더 싸지만(≈ $0.91 vs $1.24), 이 차이는 **사실상 무시 가능**하다.
- 3.5-flash-lite 는 **최신 세대의 라이트 모델**이라
  - **지시 준수·안전성**: 최신 세대일수록 프롬프트 제약(학년군 allowlist 등)을 더 안정적으로 따른다.
  - **지원 수명(deprecation 여유)**: 구세대는 먼저 종료된다(예: 2.0 계열은 2026-06-01 종료, 3.1-flash-lite-preview 는 2026-05 종료). 최신 세대를 고르면 **재이관 빈도**가 준다.
  - **세대 일관성**: 필요 시 특정 기능만 같은 세대의 상위 모델(`gemini-3.5-flash`/`3.6-flash`)로 손쉽게 상향 가능.
- 즉 **무시 가능한 비용 차이로 최신 세대의 품질·안전·수명**을 얻는다.

### 5.3 왜 구세대 2.5-flash 가 아닌가

- 라이트급 요율($0.30/$2.50)이지만 **thinking 토큰을 과다 사용**해 실측 비용이 3.5-flash-lite 의 **약 6배**, 지연은 **약 7배**.
- 구세대라 종료 시점이 먼저 오고, 문체가 장황해 저학년 눈높이엔 오히려 불리.

## 6. 리스크와 완충장치

| 리스크                              | 완충                                                                           |
| ----------------------------------- | ------------------------------------------------------------------------------ |
| 라이트 모델의 미묘한 환각·품질 저하 | JSON 스키마 검증(`ReviewService#normalize`) + 규칙기반 폴백(`RuleBasedReview`) |
| API 키 부재·호출 실패               | 무키/실패 시 규칙기반 첨삭으로 무중단 폴백                                     |
| 학년군 성취기준 이탈                | 프롬프트 allowlist + 하드 제약(전 모델 실측 위반 0)                            |
| 모델 조기 종료(deprecation)         | 최신 세대 선택으로 지원 수명 확보, 교체는 `MODEL` 상수 한 줄                   |

## 7. 재현 방법

```ruby
# rails runner 로 후보 모델을 5축 첨삭 프롬프트에 직접 호출해 비교한다.
# system_instruction = ReadingDomain.rubric_prompt(band),
# generationConfig.responseMimeType = "application/json".
# 측정: 지연, usageMetadata(promptTokenCount/candidatesTokenCount/thoughtsTokenCount),
#       grow[].standard_code 가 ReadingDomain.standards_allowlist(band) 안에 있는지.
```

- 각 모델의 엔드포인트: `POST /v1beta/models/<MODEL>:generateContent?key=…`
- 비용은 1회 실행 기준 측정치라 thinking 토큰 변동으로 오차가 있다(경향치). 개발/저볼륨은 무료 티어도 제공된다.
