## 0. 한눈에 보기

감사 리포트의 핵심 결론은 **"지금은 기능 추가보다 정합성·안전·연구증거가 먼저"** 이며, 현재 상태로 외부 공개 시연하면 위험하다는 것이었다. 이후 P1 권고를 검토해 **P1-3 감사 로그, P1-5 닉네임·랭킹 선택권, P1-8 자기성장 시계열을 구현**했다. P1-4는 기존 `accept="image/*"`와 서버 매직바이트·용량 검증을 그대로 유지하고 EXIF 제거·픽셀 상한은 추가하지 않기로 결정했다. 나머지 P1 항목은 아래 표처럼 현 단계 적용 범위에서 제외했다.

| 우선순위                  | 현재 판정                                      | 핵심 잔여 과제                                                                    |
| ------------------------- | ---------------------------------------------- | --------------------------------------------------------------------------------- |
| **P0 (외부 공개 전)**     | 기존 판정 유지                                 | 프로덕션 모드 배포, 읽기전용 심사 계정, 데모 테넌트 분리, AI 약관 준수분석        |
| **P1 (연구자료 수집 전)** | 요청 범위 3건 완료·2건 현행 유지·6건 적용 제외 | 완료: P1-3·5·8 / 현행 유지: P1-4·10 / 적용 제외: P1-1·2·6·7·9·11 |
| **P2 (일반화·접근성)**    | 기존 판정 유지                                 | 영문 임시 제목, 비경쟁 모드 배선, 몬스터 서사 레이어                              |

### ⚠️ 가장 중요한 오해 해소 — "P0 보안 3종은 코드 결함이 아니라 배포 모드 문제"
리포트가 지적한 P0 최상위 3가지는 **관찰 당시 인스턴스가 `RAILS_ENV=development`(포트 3000)로 구동된 정황**이며, 프로덕션 설정에는 이미 차단돼 있다.

| 리포트 관찰                           | 프로덕션 설정 실제                                                         | 근거                                         |
| ------------------------------------- | -------------------------------------------------------------------------- | -------------------------------------------- |
| HTTP 3000 평문 + Secure 쿠키 없음     | `force_ssl = true`(HSTS·Secure 쿠키 자동) + `assume_ssl = true`            | `config/environments/production.rb:30,33,36` |
| 비로그인 404에도 상세 Rails 오류 노출 | `consider_all_requests_local = false` + 커스텀 `public/{404,422,500}.html` | `production.rb:14`                           |
| 정상 HTML에 `BEGIN app/views` 주석    | 뷰 파일명 주석은 `development.rb`에만 존재                                 | `development.rb:74` (prod엔 없음)            |

**결론**: 이 3종은 **반드시 production 모드(Kamal/force_ssl 경로)로 배포하면 동시에 해소**된다. 코드 수정이 아니라 배포 운영 절차의 문제다. 이 영역 유일한 실질 공백은 "실수로 dev 모드로 띄우지 않도록 하는 배포 게이트"다.

| P1-5  | **랭킹 옵트인·기본숨김·실명최소화·비경쟁 경로** | **요청 범위 완료** | 닉네임 NULL 기본/강제 설정, 참여 여부 명시 선택, 비참여자 전 랭킹 집계 제외, 랭킹 실명 미노출, 나의 성장 기본 메뉴를 적용했다. 랭킹을 완전히 삭제하지 않고 원하는 학생만 닉네임으로 참여하는 구조를 택했다. |
| P1-6  | **한 축 고쳐쓰기 + 본문 근거 앵커 + AI 오류 신고** | **적용 제외** | 이번 변경 없음. |

| P1-8  | **자기비교(성장 시계열) 뷰** | **완료** | 승인된 본인 독후감 최근 12편의 최종 5축 점수와 최근 두 글의 변화를 표시하는 `growth` 화면을 신설했다. |

## 3. 권장 우선순위 로드맵

이번 P1 선택 범위는 구현 완료됐다. 이후 우선순위는 이번에 적용하지 않은 항목을 자동으로 다시 범위에 넣지 않고, 별도 의사결정이 있을 때만 재개한다.

1. **완료 상태 유지**: P1-3 감사 로그 운영 확인, P1-5 랭킹 참여율·닉네임 운영 점검, P1-8 성장 데이터가 쌓인 뒤 화면 사용성 확인.
2. **즉시 검토 가능**: 프로덕션 모드 배포 게이트(P0-1), 영문 제목 교체(P2-1).
3. **공개 전 별도 결정 필요**: 읽기전용 심사 계정(P0-3), 데모 테넌트 분리(P0-4), AI 약관 준수분석(P0-5).
4. **적용 제외 P1 재검토 조건**: 연구자료 수집·대외 제출·개인정보 처리범위가 확대될 때 P1-1·2·9·11을 우선 재검토한다. P1-4는 현행 유지에 따른 메타데이터·디코드 폭탄 잔여 위험을 운영자가 명시적으로 수용한다.

## 5. 검증 한계
- 본 대조는 2026-07-23 시점 정적 코드 기준이며, 부하시험·침투시험·법률자문·개인정보 영향평가는 아니다.
- "완료" 판정은 코드 존재·구조 근거이며, 실제 배포 환경·부하·법적 준수는 별도 검증이 필요하다.
- 개인정보·약관·대회 일정은 제출 직전 공식 원문과 현재 적용 버전을 재확인해야 한다.
- P1-4의 `accept="image/*"`는 서버 허용목록이 아니며, 현행 유지 결정은 EXIF/위치정보 잔존과 초대형 픽셀 이미지 디코드 위험까지 제거됐다는 뜻이 아니다.
