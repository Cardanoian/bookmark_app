# 실기기 검증 체크리스트 (Galaxy Tab, Phase 10)

계획 §11 을 **실제로 채울 수 있는 형태**로 옮긴 것이다. 에뮬레이터로 대신할 수 없는 항목이
남아 있어 이 단계는 기기에서 사람이 직접 해야 한다.

## 이 문서를 읽는 법

각 항목 앞에 표시가 붙어 있다.

| 표시 | 뜻 |
|---|---|
| 🟢 | **에뮬레이터에서 이미 실측했다.** 실기기에서는 "같은지"만 빠르게 확인하면 된다 |
| 🔴 | **아무도 확인한 적 없다.** 에뮬레이터로는 재현이 안 되거나 신뢰할 수 없는 항목 |
| ⚪ | 확인은 했지만 조건이 달라 실기기 결과가 의미 있는 항목 |

🟢 를 다시 전수로 도는 것은 시간 낭비다. **🔴 부터 하고, 시간이 남으면 🟢 를 훑는다.**
🟢 의 근거는 계획서 `.omc/plans/hotwire-native-android-implementation.md` §M·§N 에 있다.

> ⚠️ **에뮬레이터가 신뢰할 수 없는 것**: 실제 카메라 하드웨어, HEIC, 고해상도 사진의 메모리
> 압박, 실제 화면 크기·배율, 시스템 글꼴 확대, 실제 네트워크 단절, 제조사(One UI) WebView.
> 🔴 는 대부분 이 목록에서 나온다.

## 0. 테스트 전 기록 (§11.1)

아래를 먼저 채운다. **이게 없으면 나중에 결과를 재현할 수 없다.**

```
기기 모델명            :
Android / One UI 버전   :
Android System WebView :          ← 아래 명령으로 확인
Chrome 버전            :
화면 해상도 / 배율      :
네트워크 종류           :
APK SHA-256            :          ← 아래 명령으로 확인
versionName / Code     :          ← 현재 1.0.0 / 1
서버 배포 commit        :          ← 현재 운영: 배포 동결 판본
테스트 일시 / 수행자     :
```

**WebView 버전** (기기에서 `설정 > 애플리케이션 > Android System WebView`, 또는 USB 연결 후)
```bash
adb shell dumpsys package com.google.android.webview | grep -m1 versionName
```

**APK 해시** (제출본과 설치본이 같은지 확인하는 유일한 근거)
```bash
sha256sum chaekgalpi-android-v1.0.0-release.apk
adb shell pm path net.chaekgalpi.app   # 설치본 경로 확인 후 pull 해서 대조해도 된다
```

**서버 판본** — 앱이 붙는 서버가 무엇인지 함께 남긴다. release APK 는 항상
`https://chaekgalpi.net` 을 본다(빌드 가드가 다른 값을 막는다).

## 1. 설치 시나리오 (§11.2) — 🔴 전량 미확인

에뮬레이터는 `adb install` 만 썼다. **심사장에서 실제로 일어나는 것은 파일 관리자로 APK 를
여는 경로**이고, 그 경로의 출처 허용 안내는 제조사마다 다르다.

- [ ] 🔴 기존 `net.chaekgalpi.app` 설치본 제거
- [ ] 🔴 **My Files(또는 심사 때 쓸 같은 앱)에서 APK 열기** — `adb` 없이
- [ ] 🔴 "출처를 알 수 없는 앱" 허용 안내 처리 (몇 번 탭해야 하는지 기록할 것)
- [ ] 🔴 설치 성공
- [ ] ⚪ 앱 아이콘과 이름(`책갈피`) 확인 — 적응형 아이콘이 One UI 마스크에서 잘리지 않는지
- [ ] 🟢 첫 실행 시 서버 화면 도달
- [ ] 🔴 **같은 서명 키의 다음 후보를 "업데이트"로 설치** (versionCode +1 필요)
- [ ] 🔴 업데이트 후 로그인 상태·데이터 유지 확인

> 💡 마지막 두 항목은 **서명 키가 확정된 뒤에야** 할 수 있다(Phase 11). 지금 keystore 는
> 죽은 임시 키라 실제 키로 두 번 빌드해야 검증된다.

## 2. 화면·입력 매트릭스 (§11.3)

| | 조건 | 확인 내용 |
|---|---|---|
| [ ] | 🟢 세로 | 헤더·카드·하단 버튼·키보드 |
| [ ] | 🟢 가로 | 넓은 교사 표·사이드바·독후감 작성 |
| [ ] | ⚪ 3버튼 내비게이션 | 하단 콘텐츠 겹침 없음 |
| [ ] | ⚪ 제스처 내비게이션 | 뒤로가기와 스크롤 충돌 없음 |
| [ ] | 🟢 글자 크기 기본 | 기본 레이아웃 |
| [ ] | 🔴 **글자 크기 확대** | 버튼·텍스트 잘림 없음 — **에뮬레이터에서 안 해 봤다** |
| [ ] | 🟢 화면 회전 | 폼·내비게이션 복원 |
| [ ] | ⚪ 소프트 키보드 | 현재 입력칸과 제출 버튼 접근 가능 |

**🔴 글자 크기 확대가 이 표에서 가장 위험하다.** 초등 전학년 대상이라 실제로 크게 쓰는
학생이 있고, 데스크톱 루트 폰트 확대(`application.css`)와 시스템 글꼴 배율이 겹치면
`text-sm` 하한 규칙이 깨질 수 있다. `설정 > 디스플레이 > 글자 크기와 스타일` 최대치로 두고
독후감 작성·교사 검토 두 화면을 본다.

## 3. 심사 핵심 동선 (§11.4)

### 학생

- [ ] 🟢 앱 실행 → 로그인 선택
- [ ] 🟢 학생 데모 원클릭 로그인
- [ ] 🟢 홈과 대표 몬스터 확인
- [ ] 🟢 독서활동에서 책 선택
- [ ] 🟢 직접 쓰기 입력·제출
- [ ] 🔴 **사진으로 쓰기 → 카메라 촬영** (실제 카메라 하드웨어)
- [ ] 🟢 사진으로 쓰기 → 기존 사진 선택
- [ ] ⚪ OCR 읽는 중 → 본문 자동 반영 (실제 손글씨로)
- [ ] ⚪ 잘못 읽은 글자 수정 → 제출
- [ ] 🟢 승인 독후감의 5축 피드백·방사형 차트
- [ ] 🟢 독서 게임 실행
- [ ] 🟢 도감과 성장 화면
- [ ] 🟢 로그아웃 후 보호 화면 복귀 불가

**주의해서 볼 것**
- 제출 뒤 **뒤로가기를 눌러 본다.** 작성 폼으로 돌아가 재제출되면 안 된다(같은 글 2편 생성 —
  에뮬레이터에서 실측·수정한 결함이라 회귀 여부를 본다).
- OCR 사진의 **확대 링크**를 눌러 본다. 웹은 새 탭, 앱은 전용 확대 화면으로 가야 한다.

### 담임교사

- [ ] 🟢 교사 데모 원클릭 로그인
- [ ] 🟢 검토 목록과 상태 필터
- [ ] 🟢 학생 OCR 원본 사진 512px 표시·확대
- [ ] 🟢 5축 수정·승인 → **학생 앱 화면이 새로고침 없이 바뀌는지**(운영에서 실측 완료)
- [ ] 🟢 학생별 통계
- [ ] ⚪ **CSV 내보내기** — 저장 위치 선택 대화상자가 뜨고 실제 파일이 열리는지
- [ ] 🔴 **포트폴리오 Android 인쇄 / Save as PDF** — 실제 인쇄 서비스는 기기마다 다르다
- [ ] ⚪ 성장카드 PNG 저장
- [ ] 🟢 로그아웃
- [ ] ⚪ **문서 출력 화면**(`교사 네비 > 문서 출력`) — 4종 문서가 열리는지

### 추가 역할

- [ ] ⚪ 교무관리자 전교 통계·NEIS 요약
- [ ] ⚪ 사서 인기대출·행사·CSV 업로드
- [ ] ⚪ 총괄관리자 주요 목록과 분석

## 4. 네트워크·복구 (§11.5)

- [ ] 🟢 정상 Wi-Fi 첫 실행
- [ ] ⚪ 화면 이동 중 Wi-Fi 차단 (비행기 모드)
- [ ] ⚪ 네트워크 오류 화면과 재시도
- [ ] 🟢 Wi-Fi 복구 후 정상 이동 · 실시간 갱신 재연결
- [ ] 🔴 **OCR 처리 중 백그라운드 → 복귀** (실제 촬영 사진으로)
- [ ] ⚪ 앱 복귀 후 완료 상태 확인
- [ ] 🔴 **서버 500 / 403 / 406 의 사용자 안내** — 일부러 만들기 어려우니 최소 403(타 학급
      학생 URL 직접 입력)만이라도 본다
- [ ] ⚪ 앱 강제 종료 후 재실행

**개발자 옵션 `활동 유지 안 함`(Don't keep activities)** 을 켜고 독후감 작성 → 사진 선택 →
복귀를 한 번 해 본다. 🟢 에뮬레이터에서 통과한 조합이지만 실기기 메모리 압박이 다르다.

## 5. 사진 변형 (§11.6) — 🔴 이 절 전체가 실기기 전용

에뮬레이터 카메라는 합성 이미지라 **아래 중 어느 것도 의미 있게 검증되지 않았다.**

- [ ] 🔴 후면 카메라 세로 촬영
- [ ] 🔴 후면 카메라 가로 촬영 (EXIF 회전이 OCR 에 영향을 주는지)
- [ ] 🔴 밝은 사진 / 어두운 사진
- [ ] 🔴 **고해상도 10MB 근처 사진** — 메모리 압박으로 WebView 가 죽지 않는지
- [ ] 🔴 PNG / JPEG 갤러리 사진
- [ ] 🔴 지원되는 경우 HEIC 사진
- [ ] 🔴 촬영 취소 → 다시 촬영
- [ ] 🔴 사진 선택 취소 → 다시 선택
- [ ] 🔴 업로드 중 네트워크 단절
- [ ] 🔴 서버 제한 초과 시 친절한 오류

**가장 중요한 것**: 계획이 지목한 "12MP급 3연속 촬영 후 앱 생존". 실제 카메라로 연속 3장을
찍어 앱이 살아 있는지 본다(`onRenderProcessGone` 은 라이브러리가 처리하지만 실기기 메모리에서
확인된 적이 없다).

## 6. 결함이 나오면

재현 절차를 이 형식으로 남긴다. **"안 돼요"만으로는 고칠 수 없다.**

```
무엇을 했나  : (탭한 순서 그대로)
무엇을 기대  :
무엇이 일어남:
재현율       : 3회 중 몇 회
화면 기록    : (스크린샷 / 화면 녹화)
로그         : 아래 명령 출력
```

```bash
# 기기를 USB 로 연결하고, 재현 직전에 로그를 비운 뒤 재현한다
adb logcat -c
# ... 재현 ...
adb logcat -d -s Hotwire-Core:* Hotwire-Navigation:* chromium:* AndroidRuntime:* > 결함.log
```

`Hotwire-Core`·`Hotwire-Navigation` 태그가 방문 제안·라우팅 판정·화면 전환을 전부 남긴다.
크래시는 `AndroidRuntime`, WebView 오류는 `chromium` 에 찍힌다.
