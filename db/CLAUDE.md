# db/ — 데이터베이스 스키마·마이그레이션·시드

'책갈피'의 SQLite 데이터베이스 정의를 담은 폴더입니다. 운영(production)은 primary·cache·queue·cable **4개 DB**를 쓰며, 각 보조 DB는 Solid Cache/Queue/Cable 전용 스키마를 따로 가집니다. 애플리케이션 도메인 테이블은 primary(`schema.rb`)에 모두 정의됩니다.

## 파일

- `schema.rb` — primary DB 현재 스키마(auto-generated, 47개 테이블, version `2026_07_30_000001`). **직접 편집 금지** — 반드시 마이그레이션을 추가/실행해 재생성할 것. `bin/rails db:schema:load` 의 기준.
- `seeds.rb` — 시드 오케스트레이션. `db/seeds/accounts.yml`·`app_settings.yml`을 안전하게 읽고, 아래 rake 태스크들을 순서대로 `invoke` 하며 superadmin(총괄관리자)·**system 유저(온디맨드 캐시 소유자, origin=system Quiz 의 created_by)**·**역할별 개발 샘플 계정**·`app_settings` 기본값을 멱등 생성. (rake 상세는 `lib/tasks/CLAUDE.md`) 샘플 퀴즈는 `quizzes:seed` 가 Phase 1 콘텐츠축 컬럼(origin=teacher/content_axis=mcq/band 유도/content_version=1, 문항 mcq_single·manual)까지 채워 재현되므로 시드가 Phase 1 스키마와 함께 깨끗이 재적재된다(#9-seed).
  - 순서: `schools:seed_full`(CSV 없으면 `schools:seed`) → superadmin → **system 유저** → **비production 역할 샘플 계정** → `monsters:seed`·`badges:seed` → `books:seed_full`(TSV 없으면 no-op, 축소 폴백 없음) → **업로드 이력이 없을 때만 docs 번들 추천도서 XLSX 초기 적재** → **`books:seed_summaries`**(도서 적재 뒤 저장된 Claude 줄거리 주입, 무키·YAML 없음에도 크래시 0) → **`books:seed_quizzes`**(큐레이션 게임 문항을 CuratedQuiz 로 물질화, Stage 2) → `quizzes:seed` → **`challenges:seed`**(초기 전국·학교 챌린지) → `app_settings` → **(`SEED_DEMO=1` + 비production 한정) 데모 사용 데이터**(`db/seeds/demo_seeder.rb`가 `db/seeds/demo/*.yml` 적재) → **같은 게이트 안에서 `demo_content:seed`**(체험 계정 저작 콘텐츠 — 학급·학생·독후감이 다 있어야 붙일 수 있어 `DemoSeeder` 뒤).
  - **데모(가상 사용) 데이터**: `ENV["SEED_DEMO"] == "1"` 이고 `!Rails.env.production?` 일 때만 `DemoSeeder` 를 호출한다(운영에 가짜 아동 데이터 유입 차단, 예: `SEED_DEMO=1 bin/rails db:seed`). "이 앱을 많이 사용한 것처럼" 보이는 5개 학교·7개 학급(원동 6-1/6-2, 율하 4-2, 문덕 3-1, 유강 5-3, 효자 2-1/1-4 — 초등 전학년 1~6 커버)·학급당 담임+학생 20명·독후감·게임·몬스터·커뮤니티·미션·시즌점수·뱃지를 **학급 단위 트랜잭션 + 멱등**(학급에 독후감이 이미 있으면 그 학급 전체 skip)으로 생성한다.
  - **superadmin(총괄관리자)은 credentials(`:superadmin` → `name`·`email`·`password`)를 단일 진실로 읽어 매 시드마다 이름·이메일·비번을 동기화**(리포에 비번 하드코딩 금지). credentials 미설정 시 폴백(`총괄관리자`/`admin@example.com`/`changeme1234`). **총괄관리자도 교직원이라 이메일로 로그인**(sessions#staff_create)하므로 이메일을 부여한다. 이름을 바꾸면 이전 이름 계정은 별도로 남는다.
  - **역할 샘플 계정**: production에서는 생성하지 않는다(`DEMO_DEPLOYMENT=1` 예외). 학생·담임교사·교무관리자·사서 4종은 **가상 학교 「테스트초등학교」(neis_code `9999999`, 세종특별자치시교육청, `data_source: manual`)** 소속이며(전국 CSV 에 없는 자체 코드 — `schools:seed_full` 은 `data_source: "neis"` 행만 비활성화하므로 전국 스냅샷 재적재에도 살아남는다. 학교 행이 없으면 `seeds.rb` 가 `accounts.yml` 의 `sample_accounts.school` 값으로 직접 만든다), 역할 플레이스홀더가 아닌 **실제 사람 이름·도메인 이메일**을 쓴다: 담임 **김지은**=`jieun@gbeai.net`, 교무 **박은수**=`eunsu@gbeai.net`, 사서 **최지혜**=`jihye@gbeai.net`, 학생 **이도현**(이메일 없음, 튜플 로그인). 교직원은 이메일로, 이메일 없는 학생은 **비활성 동명 학교 + 동일 학년/반 후보가 정확히 1건일 때만** 기존 합성학교 샘플을 찾아 실학교로 동기화하며 **비밀번호는 변경하지 않는다** — 그래서 이미 존재하는 계정의 개명·이메일·비밀번호 교체는 시드가 아니라 마이그레이션 `20260727000001`(아래 #47)이 담당한다.
  - system 유저는 superadmin 과 같은 신원 규약(name + school_id:nil + classroom_id:nil)으로 `find_or_initialize_by` 멱등 생성(로그인 불가한 시스템 액터). `ContentProvider.system_user`도 같은 신원으로 멱등 확보한다.
  - 기본 `feature_flags` 에 `on_demand_games => true`(온디맨드 게임 워밍 전역 kill switch, Phase 2b C3)·`reading_discussion => true`(독서 토론 전역 kill switch, 안전 스택 동반 출하로 확대 기본)·**`account_linking => true`**(계정 연동 기본 활성, 문제 시 전역 false 하드 kill, account_linking_seasons_plan §Phase 3)·**`ranking_seasons => false`**(랭킹 시즌제 읽기 전환 스위치, 2027-03 학년도 경계에 전역 on 예정, §Phase 1/5) 포함. 스코프 오버라이드 규약은 `config/CLAUDE.md`·`app_setting.rb` 참조.
- `cable_schema.rb` — Solid Cable 보조 DB(`solid_cable_messages`). production `cable` DB.
- `cache_schema.rb` — Solid Cache 보조 DB(`solid_cache_entries`). production `cache` DB.
- `queue_schema.rb` — Solid Queue 보조 DB(잡·실행·세마포어 등 다수 테이블). production `queue` DB.

### migrate/ — 마이그레이션 (타임스탬프 순으로 도메인 그룹 적재)

primary DB 스키마를 시간순으로 쌓아 올립니다. 대략 다음 도메인 순서로 테이블이 생성됩니다.

1. **학교·사용자·학급** (`20260706000001`–`000004`): `schools` → `users` → `classrooms` → users 에 classroom FK.
2. **도서·독후감** (`20260706000005`–`000006`, `133035`): `books` → `reports`(level·reviewed 등 인덱스) → Active Storage 테이블(사진 첨부).
3. **몬스터·게이미피케이션** (`20260706140001`–`140011`): `monster_species` → `user_monsters` → users 에 active_monster FK → `shop_items` → `purchases` → `badges` → `user_badges` → `missions` → `challenges` → `seasons` → reports 에 challenge·mission FK.
4. **커뮤니티·퀴즈·도서관** (`20260707000001`–`000010`): `board_posts` → `cheers` → `stickers` → `topics` → `forum_posts` → `quizzes` → `quiz_questions` → `quiz_attempts` → `library_loans` → `library_events`.
5. **설정·보정** (`20260707000011`–`000017`): `app_settings` 생성, reports/quiz_attempts 에 `points_awarded`, users 에 `approved`(교사 가입 승인 게이트 — 이후 `20260715000001` 에서 제거), 누락 FK 일괄 추가, topics `forum_posts_count` 카운터 캐시, 랭킹용 복합 인덱스.
6. **게임 온디맨드 콘텐츠축(Phase 1~2b)** (`20260712000001`–`000004`): `quiz_questions` 에 `question_type`·`content`·`answer`·`explanation`·`difficulty`·`source` → `quizzes` 에 `content_axis`·`band`·`origin`·`generation_status`·`content_version`·`reported` + 콘텐츠축 델타 상한 지원 인덱스(`index_quizzes_on_content_axis_delta`) → 기존 데이터 백필(origin=teacher/content_axis=mcq/band 유도, mcq_single/manual; `up`/`down` 왕복 무손실) → **dedup 부분 유니크 인덱스(`index_quizzes_on_content_axis_dedup`, Phase 2b §2b.4/A2)**: `(book_id, band, content_axis, content_version)` **UNIQUE WHERE origin = 1**(정수 술어 = `Quiz.origins[:system]`; 문자열 `'system'` 금지 — 정수 컬럼과 0행 매칭 시 dedup 무효). teacher 행(origin=0)은 술어 제외로 중복 허용. `insert rescue RecordNotUnique` thundering-herd → 콘텐츠축당 1생성.
7. **FK on_delete 정합화(Phase 6)** (`20260712000005`–`000006`): 모델 nullify 의도와 어긋난 두 FK 의 `on_delete` 를 맞춘다. `reports.book_id → books`(#6)·`monster_species.evolves_from_id → monster_species` 자기참조(#8)에 **`on_delete: :nullify`** 부여 — 부모 삭제 시 자식을 남기고 참조만 끊는다(모델 `Book#has_many :reports, dependent: :nullify`·`MonsterSpecies#has_many :next_forms, dependent: :nullify` 와 정합). SQLite 는 FK 변경을 **테이블 재빌드**로 처리하므로 `up`/`down` 모두 재빌드·데이터 복사 → **왕복 무손실**(`test/models/fk_on_delete_roundtrip_test.rb` 로 검증). 컬럼 추가/삭제 없음 → 테이블 수 불변.
8. **게임 다양성 축소 + 책 소개 대결(book)** (`20260712000007`–`000009`): `quiz_attempts` 에 `hint_reveals`(whoami 서버 힌트수) 추가 후, 독서게임을 교육 다양성 우선 5종으로 줄이며 소셜 게임 `book`(책 소개 대결)을 신설. `book_intros`(user·book·classroom FK + body + votes_count, 인덱스 `[book_id, classroom_id]`) → `book_intro_votes`(book_intro·user FK, **`(book_intro_id, user_id)` UNIQUE**=소개당 1인 1표, votes_count counter_cache). 퀴즈 파이프라인 밖(Claude/Quiz 미생성). **+2 테이블(28→30)**. 축소로 제거된 게임 표면·콘텐츠축은 코드/enum 매핑 축소일 뿐이라 마이그레이션 불요(정수 컬럼 그대로).

### seeds/ — 시드 데이터

- `accounts.yml` — 총괄관리자의 credentials 미설정 시 기본값, 로그인 불가 system 유저의 신원, 비production 샘플 학교·학급·역할별 계정과 참조 관계. 운영 총괄관리자 값은 Rails credentials가 항상 우선하며 system 유저 비밀번호는 문서에 저장하지 않고 무작위 생성한다. 샘플 학급(`classrooms`)은 `academic_year` 키를 생략하면 시드 시 **현재 학년도**(`Classroom.current_academic_year`)로 생성돼 로그인 폼 기본 학년도에서 바로 조회된다(과거 학년도 샘플을 고정하려면 키를 명시).

- `book_summaries.yml` — **AI 생성 도서 줄거리 시드 자산**. 키 = 정규화 ISBN-13 문자열 → `{ title, summary }`. **출처 2종**: ① **Claude(claude-haiku-4-5) 생성분** — `BookSummaryJob` 이 세팅한 `summary_checked_at` present 인 요약만 export(네이버 blurb[checked_at nil]는 제외, 구분 신호 = `summary_checked_at`); ② **Claude 수기 보완분** — Claude 가 아직 안 채운 유명 도서 중 Claude 가 확실히 아는 책만 수기로 YAML 에 직접 채운 것(무명·불확실 도서는 정직하게 건너뜀 — 이 프로젝트의 "모르는 책 안 지어내기" 원칙). `books:export_summaries`(DB→YAML, 무키·무네트워크)로 부트스트랩·재수출, `books:generate_summaries`(Claude 키·동기)가 Claude 분 갱신, `books:seed_summaries`(무키·무네트워크·멱등)가 YAML→DB blank 매칭 도서에 주입한다(Claude 보완분은 seed 시 DB 에 checked_at 과 함께 적재돼 export 재수출도 보존). **이로써 무키 배포도 시드만으로 접지 요약을 확보**한다(AI 퀴즈 워밍 폴백·게임 가용성 게이트 §2a 의 summary 소스). Claude 보완분도 AI 생성물이라 신고·재생성 안전망 대상. **export 재수출은 DB 기준이라 수동 대량 편집분을 덮어쓸 수 있음**(먼저 seed 로 DB 반영).
- `book_quizzes.yml` — **Claude(Sonnet) 팀 생성 독서 게임 문제 시드 자산(Stage 1 데이터 + Stage 2 서빙)**. 키 = 정규화 ISBN-13 → `{ title, mcq[5], hint_reveal[3] }`. mcq=`{prompt, choices[4], answer_index(0-based), explanation, difficulty(1-3)}`, hint_reveal=`{answer(짧은 대상·문장 금지), hints[≥2 어려움→쉬움], explanation, difficulty}`. **대상: summary(줄거리)≥80자 도서와 출판사 상세 줄거리로 직접 검증한 도서 1,428권**(mcq 7,140 + hint_reveal 4,284 = 11,424문항). 제목을 묻는 첫 문항이 있었거나 줄거리·신뢰할 만한 상세 근거가 없는 도서는 정직하게 제외("모르는 책 안 지어내기" 원칙). **Stage 2 배선 완료**: `books:seed_quizzes`(무키·무네트워크·멱등)가 축별 payload 를 `curated_quizzes`(CuratedQuiz)로 upsert 하고, **그 책에 큐레이션이 최초 도입되면** 기존 origin=system Quiz(제네릭 offline·미검증 ai 캐시)를 은퇴시켜 다음 플레이가 큐레이션으로 물질화되게 한다(이미 도입된 책은 재실행 시 은퇴 스킵). `Games::ContentProvider` 가 큐레이션 우선 서빙(`fetch_ready` curated 풀 우선·MISS 물질화 source=curated)·워밍 억제(maybe_enqueue/retry_warming·`GenerateGameContentJob` 큐레이션 가드)·가용성 게이트(`game_content_available?`)로 소비한다(`db/seeds.rb` 배선 — `ENV["BOOK_QUIZZES_YML"]`로 테스트 파일 주입).

### 데모(가상 사용) 데이터 시드 — `SEED_DEMO=1` 전용

- `demo_seeder.rb` — **데모 사용 데이터 시더(`DemoSeeder` 클래스, seeds.rb 가 `require_relative`)**. `db/seeds/demo/*.yml`(학급별 1파일)을 읽어 학생·독후감·게임(game_plays·quiz_attempts)·몬스터(라인 단위 직접 지급, 진화분 evolved_at)·커뮤니티(우수작 게시판+응원·토론방+글+좋아요·책소개/뒷이야기+투표)·미션(발행 상태+goals+참여/완료/보상)을 **학급 단위 트랜잭션**으로 생성한다. **멱등**: 학급에 독후감이 이미 있으면 활동 생성을 skip 하고 학생 프로필만 동기화한다(부분 상태 없음, 재실행 no-op).
  - **증원(top-up) 경로**: 이미 독후감이 있는 학급이어도 **YAML 명단에 있고 DB 에 없는 학생이 있으면** 그 학생만 활동과 함께 새로 만든다(샘플 3-1 을 21명으로 확장하는 경로 — `pending_students`/`top_up_classroom`). 계약: ① 기존 학생의 독후감·`points`·`experience`·`season_scores`·`user_badges`·미션 원장은 **읽기만** 한다 ② 기존 학생은 새 학급 콘텐츠에 **또래로만** 참여(좋아요·응원·투표 — 포인트 무영향) ③ **기존 학생의 미션 participation 은 만들지 않는다** — 미보상(`rewarded_at: nil`) 행은 production 의 `Missions::ReevaluateJob`(`config/recurring.yml`, 매시 27분)이 목표 달성을 재평가해 나중에 포인트를 지급하므로 "기존 학생 불변"이 깨진다 ④ 학급에 **이미 발행 미션이 있으면 템플릿 미션을 새로 만들지 않고 그 미션에 신규 학생만 배정**한다(`top_up_missions` — 미션 수가 부풀지 않고 참여자 수가 학급 전원과 맞는다) ⑤ 토론방은 있으면 재사용하고 없을 때만 생성 ⑥ 재실행 시 명단 전원이 기존으로 인식돼 no-op.
  - `seed_missions` 는 `build_missions`(Mission+goals 생성) + `assign_mission`(참여·완료·보상 배정)으로 분리돼 증원 경로와 공유된다. `assign_mission` 은 완료 시각을 **미션 기간 안으로 클램프**하고 완료분에 `rewarded_at` 을 채워 재평가 대상에서 빠지게 한다. **도메인 일관성**: 포인트=경험치=Σ(독후감 등급점수[A30/B20/C10] + 게임/퀴즈 10점 + 미션보상)로 산정해 현재 학년도 `season_scores`에 같은 값 적재하고, 활동을 모두 만든 뒤 `refresh_badges!`로 실제 `ReadingStats`에서 뱃지를 부여(활동과 어긋나지 않음). 독후감 `book_title`은 카탈로그와 정확 일치 시 `book_id` 연결(미일치는 자유입력 유지). 게임/책소개/뒷이야기는 요약 있는 카탈로그 도서 풀에서 book_id를 붙인다. **비밀번호는 코드 상수**(학생 `student1234`·교사 `teacher1234`)라 YAML에 두지 않는다.
- `demo_content.yml` / `demo_content_seeder.rb` — **체험 계정 저작 콘텐츠 시드(`DemoContentSeeder`, rake `demo_content:seed`)**. YAML 이 데이터(담임 김지은의 학급 독서 퀴즈 6종×5문항 · 학생 이도현의 문제 기여 12건[approved 10 = 전국 공유 풀 물질화 / pending 2 = 담임 검토 큐] · 우수작 선정 규칙 · **사서 최지혜가 보는 도서관 인기대출 16권**[우리 학교 10 `source=csv` + 전국 6 `school_id=NULL`·`data4library`] · **이달의 책·행사 5건**[`days_from_today` 상대 날짜, 키 없으면 상시 운영])를, 시더가 로직을 갖는다. 도서관 두 블록은 정보나루 키·DLS CSV 없이도 사서 역할을 둘러볼 수 있게 하는 자료이며 학교는 담임 학급이 속한 학교를 그대로 쓴다(별도 신원 규약 없음). **독후감은 새로 만들지 않고** 이미 승인된 A등급 글만 우수작(`BoardPost`)으로 올려 응원(`Cheer`)을 채우므로 포인트·통계·시즌점수와 어긋나지 않는다. 대상 도서는 카탈로그에 있으나 `CuratedQuiz` 가 없던 책(강아지똥·책 먹는 여우·샬롯의 거미줄·나쁜 어린이 표·프린들 주세요·팥죽 할멈과 호랑이·15소년 표류기·나의 라임오렌지나무·마법의 설탕 두 조각·어린 왕자·오즈의 마법사)이라, 승인된 기여가 그 책의 `독서 퀴즈`/`나는 누구게?` 가용성 게이트(§2a)를 처음으로 통과시킨다. **멱등**: 퀴즈는 `[title, created_by, classroom]`, 기여는 `[user, book, axis] + 문항 본문`, 우수작은 **게시 여부와 무관하게 먼저 확정한 선택 집합**, 인기대출은 **`[school_id, book_title]`(period 제외 — 달이 바뀌어도 증식하지 않게)**, 행사는 `[school_id, title]` 로 판정한다(자세한 규칙은 `lib/tasks/CLAUDE.md`). 계정·학급이 없는 DB 에서는 블록별로 조용히 skip.
- `demo/*.yml` — **학급별 데모 데이터(Sonnet 에이전트 병렬 생성)**. 기본 파일은 `classroom`(school_neis_code·grade·class_no·academic_year)·`teacher`(name·email)·`missions`(goals type=approved_reports/game_plays·completion_rate)·`topics`·`students`(name + reports[book_title·body·quality(a/b/c)·reviewed·days_ago·teacher_comment?·improvement?] + game_plays·quiz_attempts·monster_lines·evolved·forum_posts·book_intro?·book_sequel?)를 둔다. 신규 학급은 검증된 활동 구성을 재사용하도록 `template`(같은 폴더의 YAML 파일명)·`student_names`(18~22명의 고유 명단)·`activity_level`(`high`/`balanced`/`low`)을 쓸 수 있다. `activity_level`은 독후감·게임·몬스터·토론과 미션 완료율을 함께 조절한다. **`student_names` 항목은 문자열(이름만) 또는 해시**를 쓸 수 있고, 해시는 `name` 외에 `nickname`(랭킹 별칭 고정 — **전역 닉네임 카운터를 소비하지 않아** 754개 상한을 쓰지 않고 뒤 파일 학급의 별칭도 밀리지 않는다), `activity_level`(그 학생만의 활동량), 그 밖의 학생 키(`reports`·`game_plays` 등 직접 지정)를 받는다. 모든 데모 학생 이름은 학급을 넘어 고유해야 하며 `DemoSeeder`가 적재 전 검증한다(닉네임도 동일). 포항원동초는 전체 39학급 중 **24학급**(약 62%)을 제공한다 — 그중 **`wondong_3_1.yml`(3-1)은 `accounts.yml` 역할 샘플 학급과 같은 학급**이라 `teacher.name`·`teacher.email`이 `accounts.yml`의 `homeroom_teacher`와 **반드시 일치**해야 하고(`seed_teacher`가 이메일로 행을 찾으므로 다르면 담임이 둘이 된다), 실사용 독후감이 이미 있어 위 **증원(top-up) 경로**를 탄다. 새 데모 학급은 18~22명으로 구성한다. 스키마·활동량 범위는 `demo_seeder.rb`가 소비하는 키가 단일 진실이다.

## 패턴·규칙

- 스키마 변경은 **마이그레이션으로만**. `schema.rb`·보조 `*_schema.rb` 직접 편집 금지.
- 모든 시드는 **멱등**(`find_or_initialize_by`/`find_or_create_by!`)이어야 재실행 안전. 새 시드 추가 시 이 규칙 준수.
- 보조 DB(cache/queue/cable) 마이그레이션 경로는 `database.yml` 에 `db/cache_migrate` 등으로 분리 지정됨(`config/CLAUDE.md` 참조).
