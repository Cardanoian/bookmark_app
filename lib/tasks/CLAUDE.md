# lib/tasks/ — rake 시드 태스크

'책갈피'의 초기 카탈로그·기준 데이터를 멱등 적재하는 rake 태스크 모음입니다. `db/seeds.rb` 가 이들을 `Rake::Task["..."].invoke` 로 호출하므로, 실제 시드 로직은 대부분 여기에 있습니다. 모든 태스크는 `find_or_initialize_by`/`find_or_create_by!` 기반이라 재실행해도 안전합니다. (`config/application.rb` 의 `autoload_lib(ignore: %w[assets tasks])` 로 오토로드 대상에서는 제외됨.)

## 파일

- `schools.rake` — 세 태스크. **`schools:seed`**(CSV가 없는 개발/테스트용 축소 17교, production no-op). **`schools:fetch`**(키 필요; NEIS 전 페이지 수집→전국 검증→정렬→임시파일 fsync/원자 rename으로 `db/seeds/schools.csv` 교체, 실패 시 기존 파일 보존). **`schools:seed_full`**(CSV 헤더·구조·17개 교육청·최소 5,000교 검증 후 1,000행 배치 upsert; 현 스냅샷 학교는 neis/active, 사라진 기존 NEIS 학교와 구 합성 17교는 삭제 대신 inactive, manual 학교는 보존). 오프라인·멱등이며 CSV 경로는 `ENV["SCHOOLS_CSV"]`, 소형 테스트 fixture는 `SCHOOLS_ALLOW_PARTIAL=1`로 주입한다.
- `books.rake` — 여덟 태스크. **`books:seed`**는 호환 태스크명으로 ISBN이 검증된 TSV가 있으면 `books:seed_full`에 위임하고, 없으면 제목-only 카탈로그를 만들지 않고 no-op 한다. **`books:seed_full`**은 `db/seeds/elementary_books.tsv`를 오프라인·멱등 적재하며 ISBN 공란·체크디지트 오류 행을 각각 집계해 제외하고, 정규화 ISBN-13으로 동일 `searched` 행까지 제자리 승격한다. TSV 값이 있는 메타만 비파괴 갱신하고 summary는 보존하며, TSV의 volume 컬럼을 정수로 적재한다(공란→nil, 시리즈 별권 구분용)(`ENV["BOOKS_TSV"]`로 테스트 파일 주입). **`books:enrich`**는 기존 ISBN 정확 일치 결과로 표지·출판사만 수동 네트워크 보강한다. **`books:deduplicate_isbn`**은 제약 도입 전 레거시의 정규화 ISBN 중복과 고신뢰 공란-ISBN 그림자를 기본 dry-run으로 보고하고, `APPLY=1`일 때만 참조 이관·메타 병합·중복 삭제한다(`INCLUDE_SHADOWS=0`으로 ISBN 중복만 제한, system quiz 충돌은 skip). **Claude 줄거리 YAML 시드 3종(`db/seeds/book_summaries.yml` — Claude 생성분만, `summary_checked_at` present 로 구분, 무키 배포도 시드로 접지 요약 확보)**: **`books:export_summaries`**(현재 DB의 Claude 생성 요약을 YAML 로 export — 무키·무네트워크, 초기 파일 부트스트랩·crash-safe 재수출 담당) · **`books:seed_summaries`**(YAML→DB, **summary 가 blank 인 매칭 도서만** summary+summary_checked_at 주입, 무키·무네트워크·멱등, ISBN 미매칭 skip, YAML 없음/빈 경우 0건 크래시 0; `db:seed` 배선 — `ENV["BOOK_SUMMARIES_YML"]`로 테스트 파일 주입) · **`books:generate_summaries[limit]`**(카탈로그[classic/recommended] 중 ①summary blank ②checked_at nil ③YAML 미포함 ISBN 인 책을 classic 우선·id asc 로 limit+일일 예산 하 **동기 처리[`BookSummaryJob.perform_now` — dev async 큐라 perform_later 금지]**, known→YAML+DB·모름→checked_at만, 각 known 직후 YAML rewrite[crash-safe]; 무키면 skip. **네트워크는 이 태스크에서만**). **큐레이션 게임 문항 로더 `books:seed_quizzes`(Stage 2)**: `db/seeds/book_quizzes.yml`(Sonnet 팀 검수 문항)을 축별(mcq/hint_reveal) payload 로 `CuratedQuiz.find_or_initialize_by([book_id, content_axis])` upsert(멱등)하고, 그 책에 큐레이션이 **최초 도입**되면(`had=false`) 기존 origin=system Quiz(제네릭 offline·미검증 ai 캐시)를 `destroy_all` 은퇴시켜 다음 플레이가 큐레이션으로 물질화되게 한다(prod 최초 seed 는 플레이 전이라 no-op). **이미 큐레이션 도입된 책(`had=true`)은 재실행 시 은퇴 스킵**(멱등·attempt 보존). 무네트워크·무키 무관. ISBN 미매칭 skip·YAML 없음/빈 경우 0건 크래시 0. `applied`/`skipped_no_match`/`retired_books` 카운트 출력. `db:seed` 배선(seed_summaries 뒤). `ENV["BOOK_QUIZZES_YML"]`로 테스트 파일 주입.
- `monsters.rake` — `monsters:seed`(전체 24라인 72폼)·`monsters:seed_phase2`(Phase 1 위에 Phase 2 12라인 36폼 추가)·**`monsters:backfill_unlocks`**(`User.student.find_each`로 기존 학생 전원의 몬스터 해금을 `MonsterUnlock#evaluate!`로 재평가 — unlock_condition 롤아웃 후 소급 지급용 배치, `(user_id, dex_no)` 유니크+미보유 가드로 재실행해도 멱등. 과거 게임 플레이는 `game_plays` 원장에 없어 게임 조건 라인은 신규 플레이부터 누적)·`monsters:install_assets`(YAML 매핑 검증 후 `sprite.png`를 256×256 정적 PNG로 변환하고 애니메이션 WebP와 함께 각각 72개를 `app/assets/images/monsters`에 멱등 설치; `ffmpeg` 필요). 종 데이터 적재는 `MonsterSeeder`가 담당하며 소스는 `db/seeds/monsters.yml`(라인 단위 `unlock_condition`은 stage 1 폼에만 포함).
- `quizzes.rake` — `quizzes:seed`. 시드된 도서 1권(기본 "마당을 나온 암탉")에 대해 게시(published) 전역 퀴즈 1개를 만들어 quiz(mcq) 게임을 즉시 플레이 가능하게 함. 문항은 `Ai::QuizDraftService` 로 5개 생성. `title` 기준 멱등. **Phase 1 콘텐츠축 메타(#9-seed)**: 퀴즈에 origin=teacher·content_axis=mcq·band(전역이라 g56 폴백)·content_version=1, 문항에 question_type=mcq_single·source=manual 을 명시해 신규 컬럼과 함께 재현되게 함(`test/tasks/quizzes_seed_test.rb`).
- `badges.rake` — `badges:seed`(뱃지 13종) + `shop_items:seed`(먹이·진화의 돌·장식 상점 아이템). 각각 `key`/`name` 기준 멱등.
- `challenges.rake` — `challenges:seed`. `db/seeds/challenges.yml`의 초기 챌린지(전국 1 + 학교 1)를 **`(scope, school_id, title)` 신원으로 멱등** 적재하고 목표를 `goal_type` 당 1개 upsert 한다(유니크 `[challenge_id, goal_type]`, `target_count > 0`). `scope: school` 은 `school_neis_code` 로 실학교를 찾아 `school_id` 를 붙이며 **학교를 못 찾으면 그 챌린지만 건너뛴다**(전국 챌린지는 계속 생성). **참여·보상 행(`challenge_participations`)은 만들지 않는다** — 챌린지는 전국/학교 스코프라 전원 eager 배정이 비현실적이어서 `Challenges::EvaluateProgress` 가 활동 트리거·상세 조회 시점에 지연 생성한다. 무네트워크·YAML 없으면 no-op. `db:seed` 배선(`quizzes:seed` 뒤 — 학교를 neis_code 로 찾으므로 `schools:seed_full` 이후여야 한다). 스모크는 `test/tasks/challenges_seed_test.rb`.
- `games.rake` — 세 태스크. **`games:warm`**(Phase 3 §3.5, A5). 카탈로그(추천/고전) 도서를 대상으로 `Games::ContentProvider.warm!` 로 **band×content_axis 워밍 잡을 사전 큐잉**해 학생 첫 플레이의 콜드-첫-오프라인 노출(특히 hint_reveal)을 줄인다(게임 재구성 Phase 1: matching 생성 경로 제거로 mcq·hint_reveal 만 워밍). 예산·rate limit·스코프 플래그를 준수하고 무키면 아무것도 적재하지 않으며(오프라인만), dedup(이미 워밍 중/AI 게시됨)은 `GenerateGameContentJob` 이 자체 가드한다. **`games:backfill_book_summaries`**(게임 재구성 Phase 4 §1d 벌크 백필). 줄거리도 없고 Claude 확인도 안 한(`summary` blank·`summary_checked_at` nil) 카탈로그(고전/추천) 도서에 `BookSummaryJob` 을 `RateLimiter` 일일 예산(`WARMING_DAILY_BUDGET`) 하 페이싱해 큐잉한다(고전 우선). **무키면 0건**(`Ai::ClaudeClient.available?` 가드로 무의미한 큐잉 차단). 잡이 멱등이라 재실행 안전. **`games:content_health`**(게임 재구성 Phase 5 §7·§8 사후 측정). **읽기 전용 콘텐츠 건강 스냅샷**(운영 모니터링용, 쓰기 0·신규 테이블 0) — 기존 substrate만 집계 출력: ①축별(mcq/hint_reveal) 서빙 소스 분포(ready·미신고 system 퀴즈의 `quiz_questions.source` offline/ai/contributed) ②`games:moderation_reject:{axis}` 캐시 카운터 ③quiz_reports 총계 + 신고율 프록시(reports/game_plays) ④summary 커버리지(있음/Claude 모름[확인·blank]/미확인) ⑤`QuizContribution` status별(pending/approved/rejected) ⑥카탈로그(recommended+classic) 게임 가용성 커버리지(AI-적격[classic·summary] 또는 어느 밴드에든 ai/contributed 실질 콘텐츠 있는 책 비율, 전 밴드 합산). 무키·빈 데이터에서도 크래시 0(0/빈 값 정상 출력). 세 태스크 모두 시드 아닌 운영 태스크(스케줄/수동 실행).
- `missions.rake` — **시드 아닌 데이터 전환 태스크**(menu_refactor 심화 §2.B, PR1). **`missions:backfill_legacy`**(멱등: 레거시 참여 `reports.mission_id` 별 `[mission, user]` 최초 시각으로 완료 `MissionParticipation` 을 `find_or_initialize` + `||=` 백필해 `ReadingStats#missions` 를 completed_at 기준으로 전환[PR2]해도 몬스터 조건이 퇴행하지 않게 보존; 실제 완료행은 skip, 레거시는 `reward_points_awarded=0`; 목표 없는 참여 미션은 `status=archived`; `created_by_id` 는 담임으로 백필) + **`missions:verify_backfill`**(학생별 old[reports distinct mission_id] vs new[완료 participation] 대조, mismatch 출력·있으면 abort — **mismatch=0 이 reader 전환 PR2 배포 게이트**). 개발 DB에 레거시 미션이 없으면 vacuously 통과(created=0).

- `account_links.rake` — **계정 연동 운영·관측 태스크(account_linking_seasons_plan §Phase 5, 시드 아님)**. **`account_links:audit`**(읽기 전용 — 총 병합·활성·되돌림 카운트 + 최근 20건 요약[생존자·이동 요약 moved_counts·수행자·시각·상태] + `PRAGMA foreign_key_check` FK 무결성. **snapshot PII[password_digest·이름]는 절대 출력 안 함** — 요약 필드만) · **`account_links:purge_credentials`**(교사 되돌리기 창[14일] 경과·미되돌림 병합 snapshot 의 `password_digest`[old_pre_merge·new_attributes 양쪽]를 nullify, **`Accounts::PurgeCredentialsJob` 공유**·멱등. **purge 후 총괄 reverse 는 구조 복원되나 복원 placeholder 는 로그인 불가 → 담임 비번 재설정 필요**를 출력·주석에 명시). 빈 데이터 크래시 0.

- `demo_content.rake` — **`demo_content:seed`**. 체험(데모) 계정이 직접 만든 것처럼 보이는 콘텐츠를 무네트워크·멱등 적재한다(데이터 = `db/seeds/demo_content.yml`, 로직 = `db/seeds/demo_content_seeder.rb` 의 `DemoContentSeeder`). ① 담임 **김지은**(`jieun@gbeai.net`)의 6-1 학급 독서 퀴즈 6종×5문항(`origin=teacher`·`scope=classroom`·`published`·`content_axis=mcq`·band 는 학급 학년 유도, 문항 `mcq_single`/`source=manual`) ② 학생 **이도현**의 문제 기여 12건(`QuizContribution` — mcq 6 + hint_reveal 6; 10건은 담임 승인까지 재현해 `Games::ContributionPublisher` 가 **system·global·band 전국 공유 풀**로 물질화[`source=contributed`], 2건은 검토 큐에 pending 으로 남음) ③ **우수작 게시판**(`BoardPost`)+응원(`Cheer`) — 새 독후감을 만들지 않고 `sample_6_1.yml`이 고정한 이도현의 승인 A등급 고쳐쓰기 1편만 멱등 확인한다. ④ **도서관 인기대출**(`LibraryLoan`) — 우리 학교분 10권(`source=csv`, 교육청 DLS 업로드 경로와 동형)과 전국분 6권(`school_id=NULL`·`source=data4library`, 정보나루 동기화 결과와 동형)을 함께 넣어 사서 화면이 **두 스코프가 섞인 실제 모습**대로 보이게 한다. `period` 는 컨트롤러의 정보나루 동기화와 같은 규칙(시드 시점의 직전 달)이며, **멱등 키는 `[school_id, book_title]` 로 period 를 뺀다** — period 를 키에 넣으면 달이 바뀔 때마다 같은 책이 새 행으로 쌓여 재실행이 증식이 된다(대신 period·count 는 매 실행 갱신). ⑤ **이달의 책·행사**(`LibraryEvent`) 5건 — `days_from_today` 상대 날짜라 언제 시드해도 지난 행사와 예정 행사가 공존하고, 날짜 키가 없는 항목은 상시 운영으로 목록 맨 뒤에 놓인다(`event_on IS NULL, event_on DESC` 정렬). ④⑤ 의 학교는 담임 학급이 속한 학교(=체험 학교)를 그대로 쓰므로 사서 계정용 별도 신원 규약이 없다 — 정보나루 API 키·DLS CSV 없이도 **사서 역할을 둘러볼 수 있게** 하려는 것이다. 대상 도서는 카탈로그에 있으나 `CuratedQuiz` 가 없던 책만 골랐다. **멱등 핵심**: 우수작 선택은 게시 여부와 무관한 규칙(대표 학생=책별 최고작 상위 1, 또래=0)으로 먼저 확정한 뒤 이미 게시된 같은 글이면 no-op 한다. 김지은·이도현·6-1 학급이 없는 DB에서는 각 블록을 조용히 skip 하므로 시더 자체가 게이트다. `db:seed`의 데모 게이트에서 `DemoSeeder` **뒤에** 호출되며, 이미 떠 있는 인스턴스에는 이 태스크만 따로 돌려 추가할 수 있다.

- `reports.rake` — **독후감 첨삭 제출 버전 운영 태스크(시드 아님, BUG_FIX_PLAN F2·F3, 2026-09-20)**. **`reports:requeue_reviews`**: 첨삭이 확정되지 않은 **현재 버전**(`completed_review_version` ≠ `review_version`)을 **같은 버전으로** 다시 예약한다 — 큐 적재 실패로 누락됐거나(primary·queue DB 가 따로라 제출 커밋과 큐 적재는 한 원자 작업이 아니다), 배포 때 구형 큐 작업(버전 없음 — 잡이 기록만 남기고 종료)에 걸려 pending 으로 남은 글의 복구 절차(§4.2-5·§7.2). 기본 대상은 제출된 글(**제출 버전 1 이상**) 중 대기·처리 중, `FAILED=1` 이면 실패한 글도(원인을 확인한 뒤 선택적으로), **기본은 dry-run 이고 `APPLY=1` 일 때만 예약**한다. 버전을 올리지 않으므로 검토 상태는 그대로고, 원래 작업이 늦게 끝나 겹쳐도 `AiReviewJob` 의 확정 조건이 결과·보상을 한 번만 반영한다. **이미 확정한 글과 초안은 어떤 경우에도 예약하지 않는다.** **`reports:audit_review_versions`**(읽기 전용, §7.3): 승인(`reviewed`)됐는데 지금 제출의 첨삭이 완성되지 않은 글(`Report#review_ready?` 거짓)을 목록화한다 — 새 공개 조건이 이 글들의 첨삭을 학생에게 숨기므로 재첨삭·재승인 대상이다. 이어서 **제출됐는데 제출 버전이 0 인 글**(정상 흐름에서는 생기지 않는다 — 어떤 경로로도 첨삭·승인되지 않으므로 버전을 바로잡아야 한다)도 목록화한다. 두 태스크 모두 글 ID·버전·상태만 출력한다(학생 이름·본문 미출력). 스모크는 `test/tasks/reports_review_versions_test.rb`.

## 패턴·규칙

- **`db/seeds.rb` 와의 관계**: 학교는 `schools.csv` 존재 시 `schools:seed_full`(없으면 `schools:seed`)을 선택하고, 도서는 ISBN이 검증된 `books:seed_full`만 호출한다(파일 미존재 시 no-op, 축소 폴백 없음). 전체 순서는 학교 → superadmin/system/sample users → monsters/badges → 도서 → 공식 추천도서 → **`books:seed_summaries`** → **`books:seed_quizzes`** → quizzes → **`challenges:seed`** → app_settings이며, `quizzes:seed`는 superadmin·도서 이후여야 한다. **`books:seed_quizzes`는 도서 적재 뒤여야** 큐레이션이 실제 Book 에 매칭된다.
