# app/javascript/ — Stimulus 프런트엔드 (Hotwire + Import Maps)

브라우저에서 동작하는 모든 클라이언트 스크립트가 모입니다. 번들러·Node 빌드 없이 Import Maps로 모듈을 로드하며, 상호작용은 Turbo(서버 렌더 부분 갱신)와 Stimulus(경량 컨트롤러)로 처리합니다. 각 컨트롤러는 특정 UI 동작만 담당하는 작은 단위이고, 외부 라이브러리 의존 없이 순수 DOM/Canvas로 구현하는 것을 기본으로 합니다.

## 파일 / 하위 리소스
- `application.js` — 진입점. `@hotwired/turbo-rails`와 `controllers`를 import해 Turbo·Stimulus 부팅
- `controllers/index.js` — `controllers/**/*_controller`를 eager-load해 Stimulus에 자동 등록
- `controllers/application.js` — Stimulus `Application` 인스턴스 생성·export(`window.Stimulus`)
- `controllers/hello_controller.js` — Rails 기본 예제 컨트롤러(동작 확인용)
- `controllers/admin_sidebar_controller.js` — 총괄관리자 콘솔(`layouts/admin`)의 반응형 오프캔버스 사이드바 토글. 태블릿/모바일(<lg)에서 햄버거로 패널을 열고(`open`/`close`/`toggle`, `-translate-x-full`↔`translate-x-0`), backdrop 클릭·Escape(`keydown.esc@window`)로 닫으며 `aria-expanded` 갱신. 데스크톱(lg 이상)은 순수 CSS(`lg:static`)로 항상 노출 — JS 미로딩 시에도 그레이스풀
- `controllers/book_basket_controller.js` — **멀티북 바스켓**(미션·챌린지 목표별 '여러 책' any-of 지정 폼 전용). 중첩된 `book_search_controller.js`가 dispatch하는 `book:selected` 이벤트를 구독해 선택한 책을 칩으로 누적한다. 로컬(카탈로그) 책은 hidden `[ids][]` 배열, 원격(네이버 🔍 검색) 책은 hidden `[isbns][]` 배열에 담는다(서버 `GoalBooks`가 제출 시 등록·중복 제거). 칩의 × 로 개별 제거, 같은 책 중복 추가는 무시, 추가 후 검색 입력·결과 목록을 리셋해 다음 책을 이어 검색한다. JS 미로딩 시엔 서버가 프리필한 칩(기존 지정 도서)만 남아 선택이 보존된다(그레이스풀).
- `controllers/book_search_controller.js` — 도서 자동완성 + **선택**. 디바운스 입력을 서버로 fetch해 결과 목록을 렌더하고, 결과 클릭 시 hidden `book_id`·표시 input·표지를 세팅한 뒤 `book:selected` 커스텀 이벤트를 dispatch한다(퀴즈·게임·독후감 공용, 이벤트 계약 불변). **멀티북 바스켓 지원(additive)**: dispatch detail 에 원격 선택이면 `isbn`(로컬은 null)을 함께 실어 `book_basket_controller.js`가 로컬/원격을 구분해 칩에 담을 수 있게 한다(기존 단일 선택 리스너는 추가 키 무시, 하위호환). **드롭다운 항목엔 고전 여부·장르 배지(`badgeElements`, 서버 `book_meta_badges`와 동일 `.badge` 스타일)를 붙인다** — 로컬 자동완성 응답의 `classic`/`genre` 필드 기반이며 원격(네이버) 결과엔 필드가 없어 자동 생략(그레이스풀). strict/fallback 모드 + `bookId`/`cover` 타깃은 선택적(없으면 표시 전용으로 동작). **시리즈 접기 2단계 드릴다운**: 결과 렌더의 `itemElement`가 디스패처로 분리돼 `series_count>1`(로컬 자동완성만 해당)이면 `seriesElement`("전 N권" 배지, `drillIntoSeries` 액션 — 즉시 선택하지 않음)를, 그 외(단권·원격·개별 권)는 기존처럼 즉시 `select`하는 `bookElement`를 렌더한다. `drillIntoSeries`가 신규 `volumesUrl` value(기본 `/books/volumes`)로 그 시리즈 전 권을 fetch해 `renderVolumes`("← 뒤로" 헤더 + 권별 "N권" 표식 목록)로 펼치고, 권 선택 시 그 권의 book_id로 확정한다. `backToResults`가 접힌 결과 목록(`lastResults`에 보관)으로 복귀시킨다. series_count가 없는 단권·원격 결과는 하위호환으로 기존과 동일하게 즉시 선택된다. **opt-in 원격검색 확장(하위호환)**: `remoteSearchUrl` value·`searchButton`/`isbn` 타깃이 있으면 검색 버튼(`manualSearch()`)이 **원격(네이버) 도서검색**을 `remoteSearchUrl`로 fetch(타이핑은 기존 `url`=로컬 autocomplete 그대로, 2-URL 분리·minChars 미강제). `select()`는 항목의 `id` 유무로 분기 — 로컬(id 보유)은 hidden `book_id` 세팅, 원격(id 없음+`isbn`)은 hidden `isbn`에 스태시하고 `book_id`는 공란(등록은 제출 시 서버가 수행, resolve/POST/async 없이 동기 유지). 셋 다 미설정이면 기존 동작과 완전히 동일
- `controllers/clipboard_controller.js` — 텍스트(NEIS 생기부 요약 등) 클립보드 복사 + "복사됨" 피드백
- `controllers/disclosure_controller.js` — 버튼 하나로 패널을 여닫는 최소 공개(disclosure) 컨트롤러. `toggle` 버튼의 `aria-expanded` 와 `panel` 의 `hidden` 속성만 맞바꾼다(`<details>` 와 달리 버튼과 내용이 떨어져 있어도 되므로, 교사 문서 출력의 "AI에게 물어볼 문장 예시 보기"처럼 **버튼은 다른 버튼과 한 줄에 두고 내용은 그 아래 전폭으로** 펼칠 수 있다). 패널은 마크업상 펼쳐진 상태로 두고 `connect()` 에서 접으므로 JS 미로딩 시 내용이 그대로 보인다(그레이스풀).
- `controllers/dex_controller.js` — 몬스터 도감 속성별 필터. 카드 표시 토글(순수 DOM)
- `controllers/growth_card_controller.js` — 독서 성장카드 PNG 내보내기. data-* 값을 Canvas에 그려 다운로드 **Android 앱에서는 `save-image` 브리지가 같은 버튼을 맡으므로 `nativeSaveAvailable`(= `<html data-bridge-components>`) 이면 스스로 물러난다.**
- `controllers/monster_care_controller.js` — 먹이/진화 연출. 스프라이트에 bounce 애니메이션 클래스 토글
- `controllers/photo_upload_controller.js` — 사진 업로드 전 Canvas 클라이언트 압축 + 미리보기(불가 시 원본 전송)
- `controllers/report_edit_controller.js` — 고쳐쓰기(수정) 폼의 저장 버튼 dirty-check. 본문 textarea 를 원본과 비교해 **달라졌을 때만 "수정하기" 버튼 활성화**(`resubmit?` 본문-변경 재첨삭 가드와 짝). 기존 글 폼(`report.persisted?`)에만 부착하고, OCR 초안으로 textarea 가 교체돼도 기준값 유지. JS 미로딩 시 버튼은 그대로 활성(그레이스풀). **비교 기준(`baseline` 값)**: 고쳐쓰기 초안이면 `_form` 이 넘기는 **원본 글의 본문**과 비교한다(줄바꿈 CRLF/LF·앞뒤 공백 무시 — 서버 `resubmit?` 의 `normalized_body` 와 같은 규칙). 자동 저장이 고친 본문을 미리 저장해 두므로 페이지를 연 순간의 본문을 기준으로 삼으면, 다시 열었을 때 이미 고친 글인데도 버튼이 잠겨 낼 수 없다. baseline 이 없으면 기존처럼 연 순간의 본문
- `controllers/report_autosave_controller.js` — **독후감 자동 저장(2026-09-12 되살림 — `docs/improve/베타피드백_통합정리.md` §5-1)**. `_form` 에 늘 붙고, `enabled` 값(= `Report#autosave_eligible?` + **글쓴이 본인이 연 화면**, 사진 첫 제출 화면·이미 낸 글·담임이 연 학생 초안 제외)일 때만 실제로 저장하며 아니면 **이탈 경고만** 한다. 저장은 임시 저장과 같은 `save_draft` 경로를 **JSON 으로**(`Accept: application/json`, `X-CSRF-Token`, **15초 `AbortSignal.timeout`**) 부르는 **서버 초안** — 입력이 멈추고 2초 뒤, 쉬지 않고 쓰면 20초마다, **새 글의 첫 저장은 첫 입력 0.8초 뒤 곧바로**(뒤따르는 입력으로 미루지 않음 — 초안이 생기기 전에 새로고침하면 빈 새 글로 돌아간다), 떠날 때(`turbo:before-visit`·`turbo:visit`·`pagehide`·`visibilitychange`·`beforeunload`)는 `keepalive` 로 한 번 더. **single-flight**(저장은 한 번에 하나, 도중 입력은 version 으로 추적해 다음 저장이 가져감). **새 글의 첫 저장이 초안을 만들면 `adoptDraft` 가 폼을 그 초안의 PATCH 로 바꾸고**(`action`·숨은 `_method` — **화면을 떠난 뒤에 응답이 와도 바꾼다**, 안 바꾸면 떠나는 사이 더 쓴 글의 마지막 저장이 create 로 한 편을 더 만든다) 주소를 편집 화면으로 바꾼다(이 화면에 있을 때만, Turbo 복원 식별자 유지). 첫 create 는 연결된 순간의 새 글 주소(`autosave_origin`)를 실어 서버가 그 주소로 다시 오면 초안을 열게 한다. **저장 응답의 `book_id` 는 요청을 보낸 뒤 책 칸(book_id·remote_isbn·book_title)이 그대로일 때만** 숨은 칸에 심는다(첫 저장 중 제목을 고치면 옛 책 id 를 도로 심던 결함). 저장마다 응답의 **`draft_version` 을 숨은 `version` 타깃**에 적어 다음 저장이 싣는다(서버가 다른 탭·기기의 더 새 초안이면 409 stale). **제출**: `beforeSubmit` 은 **새 글의 첫 저장(create)이 날아가는 중일 때만** 기다리고(PATCH 는 같은 글이라 기다리지 않음), 기다리는 동안 버튼을 잠그고 "저장하는 중이에요. 끝나면 바로 낼게요."를 띄우며 연타를 쌓지 않는다(`awaitingSubmit`). 떠나는 경고는 버튼을 누른 순간이 아니라 **`turbo:submit-start`(`submissionStarted`)** 에서 끈다(기다리다 창을 닫으면 잃었다). 제출이 네트워크 오류로 끝나면(`turbo:submit-end` 실패) 자동 저장을 되살린다. **응답 분류**: 5xx·네트워크 오류·시간 초과만 5/15/30/60초로 벌려 재시도(오프라인은 `online` 이벤트로 재개), **422 + `errors`**(검증 실패)는 재시도 없이 아이가 고칠 때까지 기다리고(`rejected`), **409**(stale/이미 제출)·리다이렉트(로그인 풀림)·401/403/404·**errors 없는 422**(다른 탭 로그아웃·다른 계정 로그인으로 보안 토큰이 바뀜)는 멈추고 "쓴 글을 복사해 둔 뒤 화면을 새로 고쳐 주세요"를 띄운다. 어느 쪽이든 저장 못 한 글은 dirty 로 남아 떠날 때 붙잡는다(예전에는 422 를 '저장 끝'으로 처리해 경고 없이 잃었다). **keepalive 한도(리뷰 #12)**: 브라우저는 keepalive 요청 본문을 한 문서에서 64KiB 까지만 보내고 넘으면 곧바로 실패하므로(한글 약 2만 자), `payloadBytes`(칸마다 128바이트 + UTF-8 바이트 어림)가 `KEEPALIVE_MAX_BYTES`(60KiB)를 넘는 글은 keepalive 없이 보내고(Turbo 이동·탭 전환은 문서가 남아 끝까지 간다), **창을 닫을 때(`beforeunload`)는 보통 요청으로 먼저 보낸 뒤 붙잡는다**(머물면 그 저장이 끝난다 — 예전에는 조용히 실패하고 경고도 없었다). **화면을 떠난 뒤(`disconnected`)에는 타이머를 걸지 않고**, 저장 못 한 글(떠나는 사이 더 쓴 글, **떠난 뒤 실패한 저장** — 2차 리뷰 #5)을 keepalive 로 **딱 한 번**(`lastChanceUsed`) 다시 보낸다(떠난 화면의 옛 글을 몇 초 뒤 다시 보내던 결함과, 저장 중에 '취소'를 누르고 그 저장이 끊기면 마지막 입력이 경고 없이 사라지던 결함을 함께 막는다). **화면 표(2026-09-13, 2차 리뷰 #2·#4)**: `connect` 가 `newKey()`(`crypto.randomUUID`, 없으면 난수 16바이트)로 숨은 `key` 타깃을 채워 모든 폼 요청(자동 저장·임시 저장·제출)에 싣는다 — 서버가 같은 화면의 재전송을 알아봐 첫 저장 재시도가 초안을 또 만들지 않고, 응답만 잃은 저장이 거짓 충돌로 멈추지 않는다. **입력 처리(2차 리뷰 #8·#9)**: `changed()` 는 제출이 나가는 중에도 입력을 세고(제출이 실패하면 저장·경고 대상), 저장 실패 뒤에는 입력마다 보내지 않고 벌려 둔 재시도 타이머(또는 `online`)에 맡긴다. 책 칸 스냅샷은 `JSON.stringify`(NUL 문자로 잇던 소스가 grep 에서 바이너리로 빠지던 문제 — #7). **요청 순번(3차 리뷰 M1)**: `stampSeq()` 가 저장 페이로드를 만들 때와 제출 직전(`beforeSubmit`, Turbo 가 폼을 읽기 전)에 숨은 `seq` 타깃에 지금 입력 횟수를 적는다 — 서버가 같은 화면이라도 이미 저장한 것보다 앞선 순번의 요청을 거절해, 늦게 도착한 옛 요청이 새 글을 되돌리지 않는다. **`unsaved` 값(M3·4차 L-B)**: 서버가 저장하지 않고 되돌려 보낸 글을 보여 주는 화면(충돌 두 가지·입력 오류 422)은 `version = 1`·`rejected = true` 로 시작해 떠날 때 붙잡는다(떠나는 순간 조용히 저장하고 보내 주면 입력 오류 화면은 같은 이유로 또 거절돼 잃는다 — 고쳐 저장에 성공하면 풀린다). 이 초기화는 `connect` 의 다른 초기값 **뒤에** 둔다(앞에 두면 `rejected = false` 가 도로 끈다 — 시스템 테스트가 실제로 잡았다). **한계**: 브라우저·앱의 '뒤로 가기'(Turbo 복원 방문)는 취소할 수 없어 충돌·입력 오류 화면에서도 경고 없이 떠난다 — '취소' 링크·Turbo 이동·새로고침·창 닫기만 붙잡는다(4차 리뷰 L-A). **새 글 화면의 409 stale** 응답에 `edit_url` 이 오면 폼은 그대로 두고 주소만 그 초안으로 바꾼다(새로 고치면 최신 글이 열린다 — 버전을 모르는 채 PATCH 로 바꾸면 버튼 한 번에 그 글을 덮으므로 폼은 바꾸지 않는다). 상태 문구("저장 중…"/"오후 2:14에 저장했어요. 다 쓰면 ‘제출하기’를 눌러요."/실패)는 `status` 타깃에 쓰고 `report-autosave:status` 로도 알린다(질문형 작성이 받아 쓴다). '저장'이 '제출'로 읽히지 않게 저장 문구마다 남은 행동을 함께 적는다. 브라우저 E2E 는 `test/system/report_autosave_test.rb`(응답을 늦추는·잃는·흉내 내는 fetch 대역으로 위험 경로를 직접 친다 — 대역은 `isAutosave`[POST + Accept JSON]로 자동 저장만 가로챈다. 책 자동 완성도 Accept JSON 이지만 GET 이다)

## 패턴·규칙
- **자동 등록**: 새 컨트롤러는 `controllers/이름_controller.js`로 추가하면 `index.js`의 eager-load가 자동 인식. 수동 등록 불필요.
- **경량·무의존**: 외부 npm 패키지 없이 순수 DOM/Canvas/Fetch로 구현. **예외는 `@hotwired/hotwire-native-bridge`
  하나뿐**이며, 이것도 CDN 이 아니라 `vendor/javascript/` 자체 호스팅이라 CSP `script-src :self` 를 유지한다. `static targets`·`static values`로 뷰의 `data-*`와 연결.
- **그레이스풀 폴백**: 클립보드·이미지 압축 등 브라우저 API 미지원 환경에서 원본 전송/폴백 경로를 둠.
- **역할 분담**: 서버 렌더 부분 갱신은 Turbo Stream(뷰의 `.turbo_stream.erb`)이 맡고, JS는 순수 클라이언트 상호작용(입력 보조·연출·내보내기)만 담당.
