# app/services/ai — 외부 AI 연동 서비스 (전부 Anthropic Claude)

독서교육 5축 첨삭·손글씨 OCR·퀴즈 초안 생성을 담당하는 AI 서비스 계층.

**제공자는 Anthropic Claude 하나다**(`ClaudeClient`, 키 `ANTHROPIC_API_KEY` — ENV 우선 → credentials 폴백). 모델만 두 갈래다: 첨삭·뒷이야기·줄거리·퀴즈 초안·퀴즈 검수는 기본 `claude-haiku-4-5`, **손글씨 OCR 만 `claude-sonnet-5`**(Haiku 는 손글씨 한글 CER 51% 로 쓸 수 없다). OCR 은 2026-09-19 까지 Gemini 였으나 Gemini API 약관이 18세 미만 대상 서비스를 금지해 걷어냈다(Gemini 클라이언트 삭제, 실측 근거 `docs/AI_MODEL_SELECTION.md` §9). 새 AI 기능도 `ClaudeClient` 를 쓴다. 키가 없거나 호출이 실패하면 각 서비스가 규칙기반/오프라인/중립값으로 폴백한다(OCR만 예외 — 폴백 없이 사진 모드 비활성화). 모든 프롬프트·루브릭 상수는 `ReadingDomain` 에 있다. **루브릭 첨삭·퀴즈 초안은 학생 학급 학년으로 학년군(g12/g34/g56)을 판별해 성취기준·눈높이 프롬프트를 분기**한다(`ReviewService`→`report.grade_band_key`, `QuizDraftService`→학급 학년; 학년 미상 시 5~6학년군 폴백). OCR 프롬프트는 학년군 무관.

## 파일
- `claude_client.rb` — Anthropic **Messages API**(`POST /v1/messages`, `MODEL = "claude-haiku-4-5"`) Faraday 래퍼. `available?`(키 존재)·`generate(contents:, system_instruction:, ...)`. 실패 시 `NotConfigured`/`ApiError` 를 던지는 것이 계약. 세 가지가 옛 Gemini 클라이언트와 다르다: ① **`contents` 는 제공자 중립 형태**(`[{ role:, parts: [{ text: } | { inlineData: }] }]`)를 그대로 유지하고 Anthropic `messages`(text/image 블록) 변환을 **이 클래스 안에만 가둔다** — 7개 호출 서비스를 건드리지 않으려는 의도적 선택이라 신규 코드도 이 형태로 넘긴다. ② **`max_tokens` 가 필수**라 `DEFAULT_MAX_TOKENS`(4096)를 항상 싣고 `anthropic-version` 헤더를 붙인다(둘 다 빠지면 실서버 400). ③ **JSON 강제 스위치가 없다** — Gemini 의 `responseMimeType` 대응물이 없어 모델이 ```json 펜스나 앞뒤 인사말을 덧붙일 수 있으므로, 펜스 제거 → 실패 시 첫 여는 괄호~마지막 닫는 괄호 salvage 순으로 두 번 파싱하고 그래도 실패해야 `ApiError`(=각 서비스 폴백)로 넘긴다. 재시도 상태코드도 Anthropic 규약(429/500/529)으로 맞췄다. **공식 `anthropic` gem 대신 Faraday 인 이유**는 리포의 외부 HTTP 규약(`connection:` 주입 + webmock 없는 `Faraday::Adapter::Test` 스텁)을 이 클라이언트만 깨지 않기 위해서다(클래스 헤더에 명문화).
- `consent_gate.rb` — **학생 PII → 외부 AI 전송의 단일 동의 게이트(P1-1)**. `ConsentGate.llm_allowed?(user, client:)` = `client.configured? && user&.ai_consented?`. 키가 있고 그 학생이 AI 활용에 동의(`User#ai_consented?` — §1 개인정보 + §2 AI 동의)했을 때만 true. 미동의·무키는 각 서비스가 기존 규칙기반/중립값으로 우아하게 강등(무키와 동형). **제공자 중립**이라 호출자가 자기 경로의 클라이언트를 `client:` 로 넘긴다(지금은 모든 경로가 `ClaudeClient`). **현재 경유 3경로: `ReviewService`(첨삭)·`SequelFeedbackService`(뒷이야기)·`OcrJob`(손글씨)**. ⚠️ 신규 AI 서비스가 학생 원문을 외부 모델로 보낸다면(book 기반 무-PII 경로가 아니라면) 반드시 이 게이트를 경유해야 한다(`grep ConsentGate` 1회로 전 PII 경로 감사). book_summary·quiz_draft·quiz_moderator 는 book 기반 무-PII 라 미게이트.
- `review_service.rb` — 5축 발전적 첨삭(RUBRIC). LLM 응답을 `{ level, rubric(5축), praise, fix, grow, pts }` 로 정규화, 무키/실패/스키마이탈 시 `RuleBasedReview` 폴백. system_instruction 은 `report.grade_band_key`로 고른 `ReadingDomain.rubric_prompt(band)` — **학년군 성취기준 전체 목록(allowlist)을 주입하고 목록 밖·상위 학년 성취기준 사용을 금지**해, 예컨대 3학년 독후감에 6학년 성취기준을 요구하지 못하게 막는다. 같은 프롬프트에 **학생 대면 문장 규칙**(무의미 입력 게이트·원문 그대로 인용과 지적 전 자기 점검·책 내용 단정 금지·해요체와 호칭 금지·나쁜 예/좋은 예 — 문구는 전부 `ReadingDomain` 상수)이 들어간다. `normalize` 는 **fix·grow 를 학년군 상한(`ReadingDomain.feedback_limits(band)`, g12 1/1·g34·g56 2/1)까지만 앞에서부터 남긴다** — 프롬프트도 같은 상한을 지시하지만 모델이 넘길 수 있어 "한두 가지에 집중" 계약을 여기서 보장한다(praise 는 자르지 않음). 무의미 입력 게이트가 지시하는 응답(praise·grow 빈 배열, 전 축 0점, C, fix 한 문장)은 정상 응답이라 폴백하지 않는다.
- `rule_based_review.rb` — 외부 호출 없는 규칙기반 5축 첨삭(무중단 폴백). 본문 길이·문장수·감정/삶 어휘 카운트로 축 점수 산출, LLM 경로와 동형 해시 반환.
- `sequel_feedback_service.rb` — 뒷이야기 이어쓰기 격려 코멘트(review_service 미러, 가벼움). 입력=학생이 쓴 뒷이야기 body(+맥락용 book.title/author). **정직한 AI**: 평가 대상이 "책"이 아니라 프롬프트에 든 "학생 글"이라 환각 없음. Claude 프롬프트는 **초등 전학년(1학년 포함) 격려형**(칭찬 1~2 + 부드러운 제안 1, **점수·등급 금지**, JSON `{comment}`). 단 **뒷이야기가 아닌 글**(자모 나열·같은 말 반복·이야기와 무관한 글)은 칭찬하지 않고 1~2문장으로 진짜 이어쓰기를 부탁한다(서툰 진짜 글은 예외). 책 내용 단정 금지·말투(해요체·호칭 금지)는 첨삭과 같은 `ReadingDomain::BOOK_FACT_RULES`·`CHILD_VOICE_RULES` 를 주입해 공유한다. 무키/실패/스키마이탈 시 `RuleBasedSequelFeedback` 폴백. 반환=코멘트 문자열.
- `rule_based_sequel_feedback.rb` — 외부 호출 없는 규칙기반 뒷이야기 격려 코멘트(무중단 폴백). 글 길이 기반 결정적 템플릿으로 **항상 긍정적** 코멘트 문자열을 반환한다(점수·등급 없음, 크래시 없음). ⚠️ LLM 경로와 달리 무의미 입력을 가려내지 못해 그런 글에도 긍정 코멘트를 낸다(`rule_based_review.rb` 도 동일) — 무키·미동의·API 실패 때만 타는 경로라 남겨 둔 알려진 한계.
- `book_summary_service.rb` — **Claude 줄거리 생성(게임 재구성 Phase 4 §1b, review_service 미러)**. 키가 있으면 "이 책을 아는가? 알면 초등 눈높이 줄거리(4~6문장)를 쓰고 확신도(0~1)를 매겨라, 모르면 모른다고 하고 혼동·작화하지 마라"를 물어(JSON `{known, confidence, summary}`) **known=true AND confidence ≥ `CONFIDENCE_THRESHOLD`(0.7) AND summary 존재**일 때만 줄거리 문자열을, 아니면 nil 을 반환한다. 무키/`ApiError`/스키마이탈/저확신/모름 모두 nil(폴백·크래시 0). **정직화(§3.1·P2-6)**: 프롬프트에 book.title·author·publisher·isbn 서지 정보만 넣고 **기존 summary 는 넣지 않는다**(자기참조 최소화 독립 인식). `BookSummaryJob` 진입점. OCR 과 달리 폴백 텍스트가 없는(=nil) 대신 저장을 건너뛰는 게 계약이다.
- `ocr_service.rb` — 손글씨 사진 → 텍스트. **`ClaudeClient` 에 `generation_config` 로 `MODEL = "claude-sonnet-5"`·`output_config: { effort: "low" }`·`MAX_TOKENS`(8192)를 넘기고 읽기 제한을 `READ_TIMEOUT`(60s, 기본 30s — 끊긴 요청의 재시도가 과금을 겹치지 않게)으로 늘려 쓰는 유일한 서비스**다(기본 모델 Haiku 를 덮는다). 사진은 `ImageProcessing::Vips` 로 **메모리에서** 긴 변 `MAX_EDGE`(1568)로 줄여 JPEG 로 보낸다 — variant 로 저장하지 않고(아이 손글씨 사본을 스토리지에 더 남기지 않음), EXIF 방향을 바로잡은 뒤 메타데이터를 지우며, Claude 가 받지 않는 HEIC 등도 풀린다. 축소 실패(libvips 없는 호스트의 `LoadError` 포함)면 원본 그대로 보낸다. **effort low 가 핵심**이다 — 기본 effort 에서 사진만 줄이면 흐린 글자에 생각이 길어져 출력 토큰이 2.5~4배로 늘고 비용이 오히려 오르며 30s 타임아웃도 넘었다(`docs/AI_MODEL_SELECTION.md` §9.4). 키가 없으면 `Unavailable` 로 사진 입력 모드 비활성화(Tesseract 등 폴백 없음), 빈 응답은 `ClaudeClient::ApiError` 로 올려 빈 본문 저장을 막는다. 프롬프트는 `ReadingDomain::OCR_PROMPT`(학년군 무관, JSON `{text}`). Sonnet 5 는 `temperature` 를 보내면 400 이다.
- `quiz_draft_service.rb` — 도서 기반 독서 게임 콘텐츠 생성(QUIZGEN/Phase 2a). 진입점 2개: **`call(book, count:, band:)`**(하위호환 mcq 초안, 교사 퀴즈 CRUD) + **`content_set(book, band, content_axis)`**(Phase 2a 콘텐츠축 세트, AI→오프라인 폴백; Phase 2b Job 진입점). AI 경로는 `ReadingDomain.content_prompt(band, axis)`로 생성 후 **`normalize`가 content_axis별 분기**(count 강제=CONTENT_COUNTS·dedup·정답 검증[mcq 정답 1개·hint_reveal 힌트 최소 2개+타깃]·해설/난이도 파싱). 무키/실패/스키마이탈 시 **`offline_set`가 book.summary/title 파생 결정적 세트**로 폴백(C2, 네트워크 0): mcq=책 제목·지은이·줄거리 토큰 파생(하드코딩 김유신/장영실/구름빵 오답 제거; `place_answer`/`pad_options` 가 오답이 3개 미만이어도[예: 줄거리가 `SUMMARY_DISTRACTOR_POOL` 낱말을 대부분 포함해 오답 후보가 부족한 경우] `GENERIC_FILLER_DISTRACTORS` 로 패딩해 **보기 항상 정확히 4개·서로 중복 없음**을 보장 — 오프라인 경로는 Moderator 게시 전 검증을 거치지 않고 학생에게 바로 노출되므로 이 계약을 서비스 스스로 지켜야 함), hint_reveal=책 제목/지은이/줄거리 토큰 타깃 + 어려움→쉬움 안전 힌트. summary 없으면 일반 독해로 우아하게 강등, 모든 축 band별 상이. 반환 해시는 두 경로 동형(`{ question_type, prompt, content, answer, explanation, difficulty }`; mcq 는 하위호환용 `choices`/`answer_index` 병기). 오프라인 품질 < AI(정직화). **게임 재구성 Phase 1**: matching(vocab) 생성 경로(`offline_matching`·`normalize_matching`·`READING_TERMS_BY_BAND`) 제거 — mcq·hint_reveal 만 생성한다(Quiz#content_axis matching·QuestionScorer matching 은 휴면 보존).
- `quiz_moderator.rb` — **온디맨드 게임 콘텐츠 게시 전 안전 검증기(Phase 2b §2b.3, R4/시나리오2)**. `review(set, content_axis:)`가 `GenerateGameContentJob`이 AI 세트를 학생에게 게시하기 **전에** pass/fail 을 판정한다(통과분만 게시, 실패분은 오프라인 유지·원문 미노출). **보장하는 것은 정확히**: ① 구조 유효성(content_axis별 count=CONTENT_COUNTS, mcq_single 정답 정확히 1개·범위 내 / matching 정답키 개수·범위·쌍 수 / hint_reveal 힌트≥2+타깃, 보기·우측 상호 배타[중복 없음], 인덱스 범위) ② 결정적 한국어 금칙어 denylist(**`Moderation::TextDenylist::QUIZ` 위임** — `DENYLIST` 상수는 그 별칭. 토론 자유입력은 오탐 낱말을 뺀 `FORUM` 리스트를 쓰지만 quiz 는 기존 동작 보존차 QUIZ 리스트 유지) ③ (선택)LLM 자가검토(키 있을 때만; 무키·실패는 거부 사유 아님). **보장하지 않는 것(정직화)**: 미묘한 환각 정답·편향·맥락 부적절 — 이는 강제 게이트가 아니라 신고(reported)+content_version 재생성+스코프 kill switch+지표로 사후 회수(ADR 잔여위험). 반환은 `Result#pass?/#fail?/#reasons`. matching 은 문항 1개에 count개 쌍을 담는 구조라 count 검증을 축별로 보정.

## 패턴·규칙
- **키 유무 폴백 흐름**: 각 서비스는 진입 시 `@client.configured?` 를 확인한다. 키가 없으면 즉시 폴백 경로(`review`→규칙기반, `quiz_draft`→오프라인 템플릿, `verify`→중립값, `ocr`→`Unavailable` 예외)로 분기하고, 키가 있어도 `NotConfigured`/`ApiError`(및 각 서비스의 `InvalidResponse`)를 rescue 해 같은 폴백으로 흡수한다. OCR 경로(`ocr_service.rb`·`OcrJob`)도 `ClaudeClient::ApiError` 를 rescue 한다. 결과적으로 AI 기능은 무중단이며 응답 형태가 LLM/폴백 간 동일하다.
- **테스트 주입**: 모든 서비스는 `initialize(client:)`(또는 `ClaudeClient.new(connection:)`)로 스텁을 주입해 네트워크 없이 검증한다. `test_helper` 가 `ANTHROPIC_API_KEY` 를 ENV·credentials 양쪽에서 비우므로 스텁을 깜빡해도 실 API 를 때리지 않는다.
- **개인정보 보호**: 예외 로깅 시 `report.body` 등 학생 원문은 로그에 남기지 않고 예외 클래스·상태코드만 기록한다(`review_service.rb`).
