# app/services — 도메인 로직 서비스 객체 계층

컨트롤러를 얇게 유지하기 위해 몬스터·랭킹·독서지표·외부 API 연동 같은 도메인 로직을 담는 PORO 서비스 계층. 대부분 `initialize(user)` 로 주체를 받아 `call`/도메인 메서드를 노출한다. 외부 연동(AI·도서검색·인기대출)은 키가 없거나 실패해도 규칙기반/로컬/빈 결과로 폴백해 절대 크래시하지 않는 것이 공통 계약이다.

## 파일
- `monster_acquisition.rb` — 노력 기반 몬스터 획득(스타터 3종 선택 + 마일스톤 발견). 가챠·랜덤 경로 없음, 라인 미보유 시에만 stage 1 폼 생성.
- `monster_seeder.rb` — 도감 시드(`db/seeds/monsters.yml` → `monster_species`). 24라인×3=72폼 전량/Phase별 적재, `evolves_from` 자동 연결, key 기준 멱등. **라인 단위 `unlock_condition`은 stage 1 폼에만 대입**(2·3단계는 nil — 재시드해도 조건이 새지 않게).
- `monster_unlock.rb` — 몬스터 라인 자동 해금 평가(`docs/monster_unlocks.md §4`). 미보유·stage1·`unlock_condition` 존재 라인만 순회해 `ReadingStats#meets?`(AND 판정) 충족 시 `MonsterAcquisition#discover_monster!`로 지급(가챠·확률·유료 경로 없음). **서비스 내부 fixpoint 루프**(최대 24라운드=라인 수 상한)로 `dex_count`처럼 발견이 발견을 부르는 캐스케이드를 한 호출 안에서 완결한다(호출부는 `evaluate!`를 1회만 호출). 개별 라인 지급 실패는 rescue 해 전체 평가를 막지 않는다. 호출부는 쓰기 트리거(승인·게임·토론·스타터) 외에 **도감 조회(monsters#index/#show)에서도 self-heal**로 1회 호출해, 트리거를 거치지 않고 조건이 충족된 라인이 고착되지 않게 한다.
- `ranking_board.rb` — 랭킹 집계(학급/포디움/학교/전국/챌린지/명예의 전당). 부작용 없는 순수 조회, 그룹 집계로 N+1 제거.
- `student_home_query.rb` — **학생 홈 조회(menu_refactor 심화 §5.1, PR5)**. 활성 XLSX의 공식 추천도서(어린이 분과, 날짜별 결정적 회전)·우리 반 인기 도서(최근 30일 승인 독후감 상위)·기존 혼합 카탈로그 책 발견("이 책은 어때요?", 공식 추천·활동책 제외, 학생+날짜 시작점과 `discovery` cycle로 6권씩 순환)·이어하기·진행 중 미션. 각 섹션 제한 수량·독립 폴백.
- `student_library_query.rb` — **내 서재 조회(menu_refactor 심화 §5.2, PR5)**. 현재 학생의 책별 활동 집계(reports·game_plays GROUP BY 후 Book 일괄 로드, 전체 활동 Ruby group_by 안 함) + kind 필터 + 책 미연결(book_id nil) 독후감을 정규화 book_title 로 레거시 그룹. `Entry`/`LegacyGroup` 읽기 전용 Struct(새 테이블 없음).
- `reading_stats.rb` — 진화·뱃지·**몬스터 해금**(unlock_condition) 조건 판정용 독서 지표 집계(포인트·독후감·스트릭 등). `meets?(condition)` 로 조건 해시를 AND 판정, 지표는 메모이즈. **Phase 3B 게임 지표**: `game_plays`(원장 총 완료 수)·`distinct_games`(플레이한 서로 다른 게임 종류 수)·`game_books`(게임으로 만난 서로 다른 책 수)·`max_daily_reports`(Asia/Seoul 제출일별 전체 기간 첫 승인 독후감의 distinct book 최댓값, 연결 `Book.title`/`book_title` 정규화로 중복 제거) 추가, `classics`는 distinct book 카운트로 변경(같은 책 반복 제출로 인한 인플레이션 방지). **`missions`(menu_refactor 심화 PR2 전환)**: 옛 `reports.mission_id`(참여) 대신 `mission_participations.completed_at`(완료)을 센다 — status 무관(archived 백필 완료 보존, 몬스터 조건 퇴행 0).
- `rate_limiter.rb` — **Solid Cache 원자 increment 기반 rate limit / 예산 유틸(Phase 2b §2b.5)**. `allow?(key, limit:, period:)`·`warming_allowed?(user_id)`(per-user 시간당 한도 AND 글로벌 일일 예산). 온디맨드 게임 워밍 방어에 쓰이며, Phase 6 #7(로그인 스로틀)이 같은 프리미티브를 재사용하도록 설계. 초과 시 호출자는 오프라인 강등/차단으로 우아하게 대응. 저장소 주입 가능(기본 `Rails.cache`; test 는 null_store 라 카운팅 스토어 주입).

## 하위 폴더
- [`ai/`](ai/CLAUDE.md) — Google Gemini 연동 AI 서비스(5축 첨삭·OCR·퀴즈생성·진위확인)와 규칙기반 폴백.
- [`games/`](games/CLAUDE.md) — 독서게임 서버 권위 채점(`question_scorer` 4종)·멱등 델타 적립(`point_award` origin 분기)·플레이 기록(`quiz_play`)·**콘텐츠축 캐시-우선 리졸버(`content_provider`, Phase 2b)**.
- `missions/` — **학급 미션 도메인 서비스(menu_refactor 심화 §2.A, 별도 CLAUDE.md 없음)**. `progress_calculator.rb`(목표 진행도 — 단건 authoritative[game_plays 는 participation 기간 Asia/Seoul clamp] + `.batch` 교사 현황 N+1 제거) · `rewarder.rb`(**정확히-1회 지급** — claim[조건부 UPDATE `WHERE rewarded_at IS NULL`]+credit[`credit_points!`]을 한 `ApplicationRecord.transaction`으로 감싸 이중지급·under-award 동시 차단, m6 목표-0/미발행 가드, 방송·후크는 커밋 후 `run_point_side_effects!`) · `evaluate_progress.rb`(단일 진입점 — 독후감 승인 `on_report_approved`[report.classroom_id 스탬프 타깃=count/trigger parity]·게임 신규 `on_game_play`[현재 소속만]·편입/잡용 `evaluate_pending`) · `assignment_sync.rb`(발행 시 학급 학생 전원 배정 `on_publish` + 편입 시 `for_user`, 각각 배정 직후 즉시 평가로 지연배정 갭 흡수, `create` 비-bang+RecordNotUnique rescue 로 멱등). 완료 판정 단일 진실은 `mission_participations.completed_at`(주기 백스톱은 `app/jobs/missions/reevaluate_job.rb`).
- `recommendations/` — 공식 추천도서 XLSX 파이프라인(별도 CLAUDE.md 없음). `xlsx_reader.rb`는 전체목록 worksheet XML의 필수 헤더를 검증하고 어린이 분과만 정규화한다(10MB·5,000행 상한). `importer.rb`는 ISBN 누락·오류가 한 권이라도 있으면 업로드 전체를 거부하고, 정규화 ISBN-13으로 Book upsert와 digest 멱등·트랜잭션 활성 교체를 담당한다. 커밋 뒤 `RecommendationCoverEnrichmentJob`을 예약해 표지 결측을 비동기 보강한다(동일 파일 재업로드도 재시도 예약).

## 소규모 하위 폴더 (별도 CLAUDE.md 없음)
- `moderation/text_denylist.rb` — **결정적 한국어 금칙어 필터(무API·공용)**. 두 소비자가 **서로 다른 리스트**를 쓴다: `QUIZ`(AI 생성 게임 콘텐츠 게시 전 검증 — 실패=게시제외 비파괴, `QuizModerator` 가 소비하며 기존 동작 보존용으로 넓음)와 `FORUM`(학생 토론 자유입력 저장 검증 — 실패=저장거부 대면실패라 `새끼`(곰 새끼)·`꺼져`(불이 꺼져) 처럼 정상어에 부분일치하는 낱말을 뺀 명백한 욕설만). `hits(text, list:)`/`flagged?`. 매칭은 부분문자열(한국어 단어경계 불명확)이라 FORUM 은 리스트 자체로 오탐을 줄인다. 잔여는 신고·교사 모더레이션으로 사후 회수(정직화).
- `books/` — 도서 검색·보강·추론·중복정리·ISBN 정규화 5파일. `isbn.rb`는 ISBN-10/13 체크디지트를 검증하고 ISBN-10·하이픈 입력을 숫자 ISBN-13으로 통일한다. `search_service.rb`는 네이버 결과와 등록 입력에도 이 정규화를 적용하고 `category: searched`로 ISBN upsert하며, 무키/실패 시 로컬 검색으로 폴백한다. `catalog_enricher.rb`는 ISBN이 있는 큐레이션 도서의 표지·출판사를 네이버 ISBN 정확 일치 결과로 제자리 보강하고, **네이버가 색인하지 못한 판본(ISBN 0건)은 정보나루 `cover_url_for` 표지로 폴백**(표지만 채우고 저자·출판사는 큐레이션 값 보존)하며 별도 searched 행을 만들지 않는다(service·library·throttle DI, 양쪽 무키 시 no-op). `deduplicator.rb`는 제약 도입 전 레거시의 정규화 ISBN 중복과 고신뢰 공란-ISBN 그림자를 대표 도서로 병합해 메타·참조를 보존한다(기본 dry-run, `APPLY=1`만 삭제). `genre_inference.rb`는 외부 API 없이 가중 n-gram kNN과 강규칙으로 10개 장르를 추론한다.
- `library/data4library_service.rb` — 정보나루(data4library.kr) OpenAPI 래퍼. `popular_loans`(인기대출, `loanItemSrch`)는 무키/실패 시 `[]` 반환(호출자는 CSV 업로드 폴백)·실패 사유는 `last_error` 로 노출. **`cover_url_for(isbn13)`(도서 상세조회 `srchDtlList`)**는 네이버가 색인하지 못한 절판·구판본의 표지 URL(`bookImageURL`)을 공급해 `CatalogEnricher` 폴백이 소비하며, 무키·실패·표지 없음 시 nil(`last_error` 는 건드리지 않아 두 메서드가 독립). **인근 도서관(§5.2): `libraries_holding(isbn13:, region:, page_size: 1000)`(`libSrchByBook` — 시도 소장 도서관 목록, 응답 `response.libs[].lib` 정규화 `[{code,name,address,tel,homepage,latitude,longitude}]`; 무키/미존재 → `[]`, 원격 실패 → **nil**로 :none 과 :error 를 구분, numFound>page_size 는 truncation 경고) + `loan_status(lib_code:, isbn13:)`(`bookExist` — loanAvailable Y→`:available`/N→`:unavailable`/에러·미존재→`:unknown`, `{status:, fetched_at:}` 반환으로 캐시 히트에도 조회시각 보존, `BOOK_EXIST_READ_TIMEOUT`=4s 짧은 read timeout).** 둘 다 `last_error` 불오염(권수는 정보나루 미제공이라 표시 안 함).
- `library/region_codes.rb` — **`Library::RegionCodes`(인근 도서관 §5.1)**. `School#region`(교육청명, 17교육청 폐집합)을 키로 정보나루 자체 시도 2자리 코드(법정동 아님 — 서울만 우연히 11=11)에 매핑하는 `SIDO_BY_OFFICE`(특별자치 개명 별칭 포함) + 주소 첫 토큰 보조맵 `SIDO_BY_ADDRESS`. `for_school(school)`(region 우선→address 폴백→nil)·`for_office`·`for_address`. 접미사 제거(전라북도→전라북) 금지.
- `library/nearby_availability.rb` — **`Library::NearbyAvailability`(인근 도서관 오케스트레이션 §5.3, PORO)**. `initialize(book:, school:, service:, cache: Rails.cache, max_libraries: 5, time_budget: 5.seconds, now:)`(cache·clock 주입 seam — `rate_limiter` 선례). `call` → `Result(state:, libraries:, as_of:)`: state=`:ok`/`:none`/`:no_key`/`:no_location`/`:error`/`:no_isbn`. 절차 = 무키가드→ISBN가드→시도코드(`RegionCodes`) 도출→`libraries_holding`(24h 캐시, nil→:error)→**gu 토큰 완전일치 필터**(주소 공백분할 `== gu`, `include?` 금지로 서구⊄달서구; gu nil=세종은 시도 전체 유지)→`max_libraries` 컷→`loan_status`(확정값만 15min 캐시 — 일시 `:unknown`은 미캐시로 회복 억제 방지, `{status,fetched_at}` 통째) 팬아웃(시간예산 초과분은 `:unknown` degrade)→as_of=표시 도서관 `fetched_at` 최소값(정직 "○분 기준" 라벨 근거). 무키·실패·주소불명 어떤 경우도 크래시 없이 degrade.
- `schools/` — NEIS 학교기본정보 연동 3파일. `gu_parser.rb`(도로명주소→시군구, 도농복합시·세종 단층제·시도 토큰 생략 대응) + `neis_fetcher.rb`(`schoolInfo` 전체 건수 기반 페이지네이션, 재시도, 국내 17개 교육청·코드 보유 초등학교 정규화; 무키는 `[]`, 원격/불완전 수집은 `FetchError`로 기존 CSV 보존) + `snapshot_validator.rb`(필수값·코드 중복·17개 교육청·전국 최소 건수 검증). connection DI로 테스트 네트워크를 차단한다.

## 패턴·규칙
- **`available?` / graceful 폴백**: 외부 연동 서비스(`ai/*`·`books`·`library`)는 클래스 메서드 `self.available?`(내부 `configured?`/`available?`)로 **키 존재 여부만** 판단하며 네트워크를 호출하지 않는다. 키가 없거나 원격이 실패하면 규칙기반 첨삭·로컬 캐시·빈 배열 등으로 폴백한다.
- **Faraday 연결 주입**: 외부 HTTP는 Faraday로 하며, `initialize` 에 `connection:`/`*_connection:` 인자를 두어 테스트에서 스텁 연결을 주입(네트워크 차단)한다. 자격증명은 `initialize(api_key:)` 기본값으로 `ENV["…"].presence || Rails.application.credentials.dig(...)`(ENV 우선, credentials 폴백)에서 읽으며, 테스트는 `api_key:` 인자로 직접 주입해 두 소스를 우회한다.
- **멱등 포인트 델타**: 재제출/재첨삭 파밍을 막기 위해 이미 지급한 최고 적립액 대비 초과분(delta)만 `User#award_points` 로 적립한다(`games/point_award.rb`·`app/jobs/ai_review_job.rb` 공통 패턴). 게임은 상한을 `quiz.origin`으로 분기한다(teacher=per-quiz, system=콘텐츠축; `games/CLAUDE.md`).
