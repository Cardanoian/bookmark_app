# app/controllers/teacher/ — 담임교사 영역

담임교사(또는 총괄)가 담당 학급을 운영하는 도구 모음입니다. AI 첨삭 완료 독후감의 검토 큐·5축 조정·승인·진위확인,
학생 관리, 학급 미션·퀴즈·루브릭 설정, 그리고 대회요건용 CSV·인쇄 문서 출력을 담당합니다.
대부분 `Teacher::BaseController` 를 상속해 `require_teacher!` 역할 게이트와 담임 학급 소유 검증(경계)을 공유합니다.

## 파일
- `base_controller.rb` — 네임스페이스 가드 + 공통 헬퍼. `require_teacher!`(교사/총괄 외 403) + `teacher_classrooms`·`owned_classroom!`·`owned_student!`·`axis_averages`. **`axis_averages` 는 다형(#3)**: Relation 이면 `SUM(COALESCE(json_extract(rubric,'$.axis'),0)) / count` **SQL 1쿼리**(행 미인스턴스화), Array 면 인메모리 집계(이미 로드된 슬라이스 재사용). 두 경로 값 동일(parity 테스트).
- `dashboards_controller.rb` — 교사 대시보드(`show`). 독후감 통계·5축 평균·약점 인사이트·향상도·검토 큐 요약(SQL 집계로 경량 로드). **약점 인사이트 학년군 정합**: `weakness_insight`가 담임 학급 집합에서 `dashboard_band(@classrooms)`로 대표 학년군을 파생해 `ReadingDomain.achievement_standards(band)`·`recommended_activities(band)` 로 성취기준·추천활동을 학급 눈높이에 맞춘다(단일 밴드=그 학년군, 여러 밴드가 섞이면[총괄=Classroom.all·교차-밴드 겸임] g56 종착 폴백 — 전교 통계와 동일 관례. flat g56 상수 고정으로 3학년 학급에 6학년 기준이 뜨던 문제 해소). **학생 기여 문제 검토(Phase 3 §4.3)**: 담임 학급 학생들의 pending `QuizContribution` 건수(`@pending_contributions_count`)를 "✍️ 학생 기여 문제 검토" 섹션에 노출(있을 때만)하고 검토 큐(`teacher_quiz_contributions_path`)로 링크한다. 5축 평균은 Relation 을 `axis_averages` 에 넘겨 SQL 경로를 탄다(별도 rubric 행 로드 제거). **무게이트 롤아웃 사후 검토(교사 알림)**: 담임 학급 학생이 신고한 온디맨드 게임 콘텐츠(`QuizReport`)를 "🚩 신고된 게임 콘텐츠" 섹션에 노출한다(1건만 있어도 사후 점검, 2건이면 자동 숨김). **신고된 토론 글(reading_discussion)**: **저자(작성자)가 담임 학급 소속**인 forum_post 중 reports_count>0 을 "🚩 신고된 토론 글" 섹션에 노출한다(신고자 학급이 아니라 저자 학급 기준 — 담임 모더레이션 권한과 정합). 자동 숨김이 없으므로 1건이라도 교사가 직접 확인·숨김.
- `forum_moderations_controller.rb` — 토론 글 수동 모더레이션(`hide`/`unhide`, reading_discussion). `owned_student!(post.user)` 로 **저자 학급 소유**를 강제해 담임이 자기 학급 학생 글만 숨김/해제한다(학교-스코프 토픽의 타 학급 저자 글은 403). 숨김 시 `hidden_by` 귀속. 자동 숨김이 없는 대신 이 수동 경로 + 총괄 `Admin::Moderation` 이 실제 숨김을 담당(집단신고 괴롭힘 방지).
- `reviews_controller.rb` — 검토 큐(`index`)·수정(`update`, **AI 첨삭 텍스트 편집**+5축 ±조정+코멘트)·승인(`finalize_approval`)·일괄승인(`batch_approve`)·진위확인(`verify`). **피드백 텍스트 편집(report-review-gate)**: `update`가 `teacher_feedback` permit으로 교사 편집 AI 첨삭 텍스트(칭찬/보완 줄 단위 textarea → 배열, 성장 항목별 고정 text 입력[standard_code 읽기전용])를 수용하고 `Report#teacher_feedback` JSON에 저장한다. 성장 항목별 standard_code는 **폼 입력을 신뢰하지 않고 서버에서 원본 rubric으로 재설정**(위조·오정렬 이중 방지). 승인 전 편집은 방송 미발생(비노출 유지). **승인(`finalize_approval`) 시 상세 방송 추가**: 뱃지·진화 재계산 + **미션 진행 평가**(`Missions::EvaluateProgress#on_report_approved`, menu_refactor 심화 §2.A.3 — `evaluate_monster_unlocks` **앞**에 두어 미션완료→몬스터해금이 같은 요청에 반영되며, 반환값은 그대로 `evaluate_monster_unlocks`[discovered 배열]로 유지해 `batch_approve`의 `concat` 을 깨지 않는다) + **챌린지 진행 평가**(`Challenges::EvaluateProgress#on_report_approved`, 미션 평가 뒤·몬스터 해금 앞) + **몬스터 해금 재평가**(`evaluate_monster_unlocks`, flash 안내) + **검색 캐시 도서 승격**(`report.book&.promote_from_search!` — 승인 독후감이 붙은 `searched` 도서를 정식 카탈로그 `recommended`로 올려 독서활동 허브·자동완성·발견 정상화, 멱등) + **`Report#broadcast_detail_refresh`로 학생 show 상세 라이브 방송**(승인·편집된 첨삭 텍스트·등급이 학생 화면에 실시간 노출, 내부 rescue 보존해 방송 실패가 approval 상태를 뒤집지 않음). 승인 후 `reviewed?` 상태에서 교사가 다시 `update`로 텍스트를 정정하면 동일하게 상세 방송 발생(학생 다음 로드에 반영 → 승인 후 재편집). 등급을 바꾸는 `update`도 저장 직후 동일하게 재평가한다.
- `students_controller.rb` — 담임 학급 학생 관리(`index`/`create`/`destroy`) + `reset_password`·`give_points`(수동 포인트). 학생 추가와 비밀번호 초기화는 교사가 **6자 이상 비밀번호를 직접 입력**하며, 빈 값·공백·6자 미만은 저장하지 않는다. 성공 플래시에는 입력 비밀번호를 다시 노출하지 않고, 초기화도 `owned_student!` 학급 경계를 먼저 통과해야 한다.
- `missions_controller.rb` — 담임 학급 독서 미션 관리(**menu_refactor 심화 PR4 재작성**, 발행 후 잠금 해제). `GoalBooks` include. draft 생성(제목·설명·기간·**고정 2목표**[승인 독후감·게임, `mission[goals][<type>]` target 양수만]·**종류별 '여러 책' any-of 허용목록 지정**[`mission[goal_books][<type>][ids/isbns]` — `GoalBooks#resolve_goal_book_ids`가 로컬 `ids`(비-searched 카탈로그 도서만 연결)·원격 검색 `isbns`(제출 시 등록+`promote_from_search!` 승격)를 book_id 목록으로 확정, 비우면 "아무 책이나" 인정]·보상 포인트) → **발행(`publish` member)**=`Mission#publish!`로 draft→published 전환 + `AssignmentSync` 학급 학생 자동 배정. **소유 교사(`owned_classroom!`)는 발행 후에도 목표·기간·보상을 수정하고 삭제할 수 있다**(학급은 생성 시 고정 유지 — `mission_params.except(:classroom_id)`): `update`는 상태 무관 full 적용(`apply_goals`로 목표 재구성) + 저장, `destroy`는 상태 무관 삭제. `published_requires_goal` 모델 검증은 유지(발행 미션은 목표≥1이라 목표를 전부 비우는 수정은 저장 거부). `index`는 status 필터, `show`는 `ProgressCalculator.batch`로 학생별 진행 현황(N+1 없음). 소유 학급만(`owned_classroom!`, 타 학급 접근 403).
- `quiz_contributions_controller.rb` — **학생 기여 문제 검토·수정 큐(게임 재구성 Phase 3 §4.3·§4.4)**. `index`(담임 학급 학생들의 pending 기여)·`update`(문항 내용 수정+밴드 지정, 승인 없이 저장)·`approve`(**현재 저장된 페이로드/밴드**를 그대로 `Games::ContributionPublisher`로 **system·global·band 풀 퀴즈 + contributed 문항 물질화**=전국 편입, approved 전이+reviewed_by)·`reject`(미편입, rejected). **담임만**(`owned_student!(contribution.user)`로 저자 학급 경계 강제 — 크로스-학급 403). **수정 저장(PATCH update)·승인(POST approve)·반려(POST reject)는 뷰에서 서로 다른 형제 폼**(non-nested)이다 — 뷰가 승인 버튼을 수정 폼(`method: :patch`) 안에 `formaction`/`button_to` 로 중첩시키면, 브라우저가 그 폼의 히든 `_method=patch` 를 POST 제출에도 실어 `Rack::MethodOverride` 가 요청을 PATCH 로 승격시켜 approve 라우트가 404 나는 버그가 있었다(수정됨). 이 분리로 **승인은 편집 파라미터를 받지 않으므로**, 내용을 고칠 게 있으면 먼저 저장(update) → 승인(approve) 2스텝이다. `apply_edits!`는 **update 전용**이며, 페이로드 필드가 일부 누락된 요청에서도 기존 값을 보존(빈 파라미터 덮어쓰기 방지). 승인=검증+물질화+approved 저장을 한 트랜잭션으로.
- `quizzes_controller.rb` — 학급 퀴즈 CRUD + 도서 선택 시 `Ai::QuizDraftService` 초안 문항 생성 → 검수 후 published. **도서 선택은 전량 로드 `collection_select` 대신 공용 도서 자동완성(`books#autocomplete`)**을 쓰고, `create`/`update`는 넘어온 `book_id`가 실제 비-searched `Book`인지 서버에서 검증한다(위조·searched 캐시 주입 차단).
- `account_links_controller.rb` — **계정 연동(MERGE) 교사 보조(account_linking_seasons_plan §Phase 4)**. `index`(담임 학급으로 향한 병합 원장)·`new`(현재 학급 학생 NEW 선택 + `?old_name=` 후보 작년 계정 이름검색[학교·과거 학년도])·`create`(**`owned_student!(new_account)`로 NEW 가 자기 학급 소속임을 강제** + `valid_old_candidate?`[학교·과거 학년도 서버 검증] → `Accounts::MergeService#call` 공유 + 커밋 후 `run_post_commit_side_effects!`, **세션 스왑 없음**[교사 세션 유지])·`reverse`(member — `owned_merge!`[to_classroom 이 자기 학급]·**14일 창**[`REVERSE_WINDOW = AccountMerge::TEACHER_REVERSE_WINDOW` 단일 상수 공유, 창 밖은 총괄 위임]·미되돌림만 → `AccountMerge#reverse!(performed_by:)` + 커밋 후 `run_reverse_side_effects`[생존자 랭킹/시즌 방송 갱신, 뱃지 미회수]). **동시 되돌리기·유니크 충돌은 `AccountMerge::ReversalError` rescue → alert 리다이렉트**(raw 500 방지). 크로스학급 create/reverse 는 403.
- `rubric_configs_controller.rb` — 학급 루브릭 5축 가중치 설정(`edit`/`update`). 0..5 클램프, 채점에 반영.
- `exports_controller.rb` — 독후감 사전·사후 5축 비교 원자료 CSV(`reports_csv`). gem 없이 RFC 4180 인코딩.
- `prints_controller.rb` — 인쇄용 HTML(`layout "print"`): `award`(표창장)·`home_letter`(가정통신문)·`portfolio`(포트폴리오)·`class_report`(학급 리포트).

## 패턴·규칙
- **역할 게이트**: `Teacher::BaseController#require_teacher!` 가 교사/총괄 외 전 역할을 403 으로 차단하고, `verify_authorized` 를 스킵한다(per-action Pundit 아님).
- **학급 경계**: 학급·학생·미션·퀴즈 접근은 `owned_classroom!`/`owned_student!` 로 담임 소유를 검증한다(타 학급 주입 시 403). 생성 시점에만 학급을 고정하고 update 에서 `classroom_id` 재배정을 막는다.
- **예외 — `reviews_controller.rb`**: 유일하게 `ApplicationController` 를 직접 상속하며, per-action `authorize ... ReportPolicy`(review?/approve?/verify?)로 인가한다. index·batch_approve 만 `ensure_reviewer!` 역할 게이트 + `verify_authorized` 스킵.
