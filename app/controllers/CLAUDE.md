# app/controllers/ — 컨트롤러 계층 (요청 처리·인가·리다이렉트)

'책갈피'의 HTTP 요청을 받아 인가·조회·상태변경 후 뷰/Turbo Stream/JSON 으로 응답하는 계층입니다.
모든 컨트롤러는 `ApplicationController` 를 상속하며, 인가는 **Pundit**(정책·스코프)으로 처리합니다.
네임스페이스 없는 최상위 컨트롤러는 학생·공용 화면을, `admin/`·`teacher/`·`games/`·`librarian/`·`school_admin/`
하위 네임스페이스는 역할 전용 화면을 담당합니다. 라우트 근거는 [`config/routes.rb`](../../config/routes.rb) 참고.

## 파일
- `application_controller.rb` — 전 컨트롤러의 베이스. 로그인/정지 세션 게이트 + `verify_authorized` fail-closed 인가 안전망 + Pundit 403 처리. **이메일 인증 배너·게이트**: `email_verification_banner?`(helper_method — 발송 가능 환경 && 미인증 교직원일 때만 true. 무키 환경에서 '다시 보내기'가 죽은 버튼이 되지 않게 게이트) + `require_verified_email!`(before_action 용 — `User#email_verification_gate_active?` 인 교사를 되돌린다. **fail-open**: 무키 환경·가입 24시간 유예 내에는 발동하지 않고, 발동해도 읽기 경로는 계속 열려 있다. 현재 적용 대상은 `Teacher::StudentsController#create`·`#reset_password` 둘뿐). **학생 랭킹 프로필 게이트(P1-5)**: 로그인 학생의 `nickname`이 NULL이면 `ranking_preferences#edit`로 강제 이동(설정·세션 액션은 루프 방지 skip)시켜 닉네임과 랭킹 참여 여부를 처음 한 번 명시하게 한다. **`audit!` 헬퍼(P1-3)**는 `AuditLogger`로 실행자·대상·학교/학급·요청 IP/UA·최소 메타데이터를 기록해 교사/관리자 상태변경 컨트롤러가 공용 사용한다. 그 밖에 **`MonsterDiscovery` concern include**(`evaluate_monster_unlocks`/`with_discovery`를 전 컨트롤러에 공용 제공, Phase 3B) + **`reading_discussion` 기능 플래그 게이트**(`reading_discussion_enabled?` helper_method + `require_reading_discussion!` before_action용 — 미설정 기본 활성[default: true], 전역 false=하드 kill, 스코프 오버라이드 우선; before_action redirect 는 이후 콜백·verify_authorized 를 스킵하므로 게이트 차단 시 안전망 예외 안 남).
- `dashboard_controller.rb` — 루트(`/`). 역할별 홈 화면으로 분기 렌더(학생·교사·교무·사서). **학생 루트는 홈(menu_refactor 심화 PR5)** — `StudentHomeQuery`(`discovery`·`recommend`·`popular` 순환 파라미터)로 공식 추천도서·우리 반 인기 도서·책 발견("이 책은 어때요?")을 준비하고, 미션·챌린지는 진입 카드용 **개수만**(`@active_mission_count`=`StudentHomeQuery#active_mission_count`, `@joinable_challenge_count`) 계산한다(전체 기록은 내 서재, 미션 상세 내역은 `missions#index`, 챌린지는 `challenges#index`로 이동). 총괄(superadmin)은 렌더 없이 `/admin` 콘솔로 리다이렉트.
- `libraries_controller.rb` — **내 서재(menu_refactor 심화 PR5, `resource :library`)**. `StudentLibraryQuery`로 현재 학생의 책별 활동(독후감·게임) 집계 + kind 필터(전체/독후감/게임) + 책 미연결 레거시 독후감 그룹. 표현·본인전용(Current.user 스코프)이라 `verify_authorized` 스킵 + 비학생 루트 리다이렉트.
- `reading_activities_controller.rb` — **독서활동 허브(menu_refactor 심화 PR5, `resource :reading_activity`)**. book_id 없으면 책 선택(등록 도서 자동완성), 유효한 **등록(비-searched) 도서**면 활동 선택(독후감/게임 진입)+최근 활동+미션 문맥. **가용성 게이트(게임 재구성 Phase 4 §2b)**: `@quiz_available`/`@whoami_available`(`Games::ContentProvider.game_content_available?` — AI-적격[classic·summary] 또는 그 책·밴드·축의 ai/contributed 콘텐츠 존재)을 세팅해 뷰가 퀴즈·나는 누구게? 칩 표시를 게이트한다(책 소개·뒷이야기는 항상). **`bootstrap_book_summary`(자가치유, code-review 후속)**: 가용성 게이트가 비활성 책은 `Games::ContentProvider.resolve` 전에 리다이렉트시켜 `content_provider` 의 §1d 온디맨드 트리거(줄거리 확인 큐잉)가 절대 안 걸리는 사각지대를, 학생이 책을 고르는 이 화면에서 직접 `BookSummaryJob.perform_later`(summary blank·checked_at nil·`Ai::ClaudeClient.new.configured?` 일 때만, 무키는 큐잉 안 함)로 메운다 — 아는 책이면 다음부터 가용해지는 온디맨드 자가치유 경로. searched·미존재 book_id 는 무시하고 책 선택 상태로 되돌린다(개인 데이터는 book_id 만으로 조회 안 함). 표현·본인전용이라 `verify_authorized` 스킵 + 비학생 리다이렉트. **`#nearby_libraries`(인근 도서관 §5.4, Turbo Frame lazy-load 전용)**: `resolve_book(params[:book_id])`(searched·미존재 제외)로 책 확정 후 `Library::NearbyAvailability.new(book:, school: Current.school).call`(Current.school nil 가능 → 서비스가 가드) 결과를 `_nearby_libraries` partial 로 렌더한다(책 없으면 서비스 미인스턴스화, 빈 프레임). 첫 show 렌더는 이 액션을 호출하지 않아(lazy) 외부 API 비차단.
- `reports_controller.rb` — 독후감 CRUD + `revise`(고쳐쓰기) + `share`(우수작 공유 토글). `destroy`는 작성 학생 본인만 목록에서 실행한다. 제출 시 `AiReviewJob` 예약. index 는 페이지네이션(PER_PAGE=20). **`submit_for_review` 는 `reports.submitted_at` 의 유일한 기록 지점**(재제출은 최초 시각 보존) — OCR 초안은 사진 업로드 시점에 이미 영속화되므로 "레코드가 있다 = 제출했다"가 성립하지 않고, 제출 사실을 `ai_status` 로 추론하면 `OcrJob` 이 찍은 done 이 첨삭 완료로 오인돼 교사 큐에 초안이 샌다(`Report#submitted?` 주석). **자기 독후감 열람 필터(요구 2)**: index 가 `policy_scope(Report)`(학생=본인 스코프) **위에** `book_id`/`book_title`(squish 정규형, 레거시 nil-book)/`reviewed=="true"` 필터를 얹어 위조 파라미터로도 남의 글에 도달하지 못하게 하고, `@book`·`@reviewed_filter`·`@book_title_filter` 로 필터 문맥(헤딩·배지·전체보기)을 넘긴다(내 서재 책 제목·마이페이지 타일에서 진입). **직접쓰기 학습단계(요구 1a)**: `new` 가 분기 이전에 `@guided = ReadingDomain.guided_questions(ReadingDomain.guided_band_for(Current.user.classroom&.grade))`(학년 미상→g12)를 무조건 세팅해 `_guided_compose`(직접쓰기 안내 질문)·`_photo_guide`(사진쓰기 가이드)가 소비한다. **학생 편집 경로는 고쳐쓰기 단일화**(상세 화면 제자리 '수정' 버튼 제거, `edit`/`update` 액션은 고쳐쓰기 저장에 계속 사용). **revise 는 동일 본문 재첨삭 AI 호출을 스킵**(#misc): 부모 첨삭 결과(rubric/avg/level)를 이어받아 done 으로 시작하고, 학생이 본문을 고쳐 저장하면 update 의 `resubmit?` 가드(작성자 본인+본문 변경 시에만)가 실제 재첨삭을 예약하며 안내도 "다시 첨삭 중"으로 분기. 완료는 AiReviewJob 이 상세 영역을 라이브 교체(수동 새로고침 불필요). **update 는 `resubmit?` 외에 `first_review?`(본인+`revision_of` 없음+`rubric` 공란=미첨삭) && 본문 존재 시에도 첨삭을 예약**해, OCR 초안을 텍스트 수정 없이 그대로 제출해도(본문 미변경) 첫 AI 첨삭이 걸리게 한다(revise 초안은 revision_of 존재로 제외). **제출 시 원격 책 등록(비차단)**: `create`가 `report_params_with_registered_book`에서 `book_id` 공란이고 검색 버튼으로 고른 `report[remote_isbn]`(컬럼 아님 → `params.dig`)이 있으면 `Books::SearchService#register`(캐시-우선)로 `book_id` 를 확정한다 — **`@report.save` 밖 저장 전처리**라 register 가 nil/실패여도(무키·미일치) save 를 막거나 롤백하지 않고 `book_title` 폴백으로 저장된다. **등록된 책은 `Book#promote_from_search!`로 정식 카탈로그(recommended)로 즉시 승격**한다(검색해서 독후감 쓴 책 = 실제로 읽힌 책 → searched 캐시가 아니라 검색·게임·발견에 바로 노출, 작성 즉시 등록). `prefill_attributes`(new 프리필)와 `report_params` permit 에 `:book_id` 포함(자동완성/책 고르기 스텝이 채운 값 수용, `resolved_book_id`가 위조·스테일 id 재검증).
- `ocr_controller.rb` — 사진 업로드 → 손글씨 OCR 초안(`create`). **거부 검사(Gemini 키 없음 → 책 참조[book_id/book_title] 없음 → 사진 없음)를 draft 생성 이전에 배치**해 `book_reference_present` 실패로 인한 500·빈 첨부 고아 draft 를 막는다(가짜 "사진 독후감" placeholder 제거, `book_id`도 수용). **유효 book_id 는 가드 앞에서 `resolved_book_id(ocr[book_id]) || register_and_promote(ocr[remote_isbn])`로 계산**(검색 버튼으로 고른 원격 책을 제출 시 캐시-우선 등록 + `Book#promote_from_search!`로 정식 카탈로그 즉시 승격해 링크 — `ReportsController` 미러; register 는 nil degrade라 실패 시 `book_title` 폴백으로 가드 통과). 성공 시 draft 생성 + `OcrJob` 예약 후 **compose(edit) 화면으로 redirect**(Turbo 가 302 를 따라 Visit → editor 채널 구독 → OcrJob 방송이 본문 채움). **AI 동의 게이트(P1-1)**: 키(ocr_available?) 가드 직후 draft 생성 이전에 `Current.user&.ai_consented?`를 확인해, 미동의 학생은 손글씨 사진(PII)을 Gemini 로 보내지 않도록 조기 거부한다(`_mode_chooser` 사진 카드 은닉과 짝 — URL 직접 요청 방어, OcrJob 게이트가 인플라이트 백스톱).
- `report_photos_controller.rb` — **OCR 손글씨 사진(아동 PII) 인증 프록시(`show`, `GET /reports/:id/photo`, ocr_photo_display_plan)**. Active Storage 기본 서명 URL 은 세션 없이 접근 가능한 **무인가 바이트 표면**이라 이 앱의 `verify_authorized` fail-closed 철학과 어긋나므로 도입하지 않고, 요청마다 `authorize report, :show?`로 **페이지 인가를 그대로 미러**한다(`review?`로 좁히면 학생 본인·동일학교 사서/교무가 자기 화면의 사진을 못 본다). `Report#display_photo`(고쳐쓰기 root 체인 승계)로 사진을 찾고, 표시용 512px·확대용(`?size=original`) 1600px **유계 variant**만 서빙한다 — 무제한 원본은 어떤 경로로도 내보내지 않는다(`Blob#download`가 blob 전체를 메모리에 올려 10MB 원본 동시 요청이 워커 메모리 스파이크가 되므로). **rescue 스코프는 `authorize` 이후 variant 처리 구간에만 국한**해 조회·인가 예외가 전파(404/403)되게 하고(폴백이 인가를 우회하지 않음), variant 실패는 원본 폴백으로 무중단 degrade 한다. rescue 가 `StandardError`뿐 아니라 **`LoadError`도 잡는 이유**: libvips 미설치 환경의 `.processed`는 ruby-vips 로딩 `LoadError`(< ScriptError)를 던져 `rescue => e`로는 안 잡히고 500 이 된다. 반복 요청은 `fresh_when(photo.blob, public: false)` 조건부 GET(304)으로 Puma 워커 부하를 끊고, 로그에는 report id·예외 클래스만 남긴다(URL·바이트 미로깅).
- `books_controller.rb` — 도서 카탈로그(`index`)·상세(`show`)·검색(`search`, 네이버 자동완성 JSON, 무키 시 로컬 폴백)·자동완성(`autocomplete`, 로컬 카탈로그[비-searched]만 조회하는 도서 자동완성 JSON `{id,title,author,publisher,cover_url,genre,classic,volume,series_count}` — `Book.autocomplete_grouped`로 시리즈 별권을 대표 1행으로 접고 `series_count`를 함께 낸다[series_count>1 이면 프런트가 배지+권 선택 2단계로 분기, 단권(=1)은 즉시 선택]; genre·classic 은 드롭다운 배지용, 외부호출 0 — 퀴즈·게임 도서 선택용)·**시리즈 권 목록(`volumes`**, 시리즈 접기 드릴다운 2단계 전용 신규 액션 — 첫 자동완성 응답의 title·author를 받아 `Book.series_volumes`로 그 시리즈 전 권을 권차 순 JSON`{id,title,author,publisher,cover_url,genre,classic,volume}`으로 반환, 로컬 전용·외부호출 0, 인가는 `search?` 재사용)·**원격검색(`remote_search`**, 검색 버튼 전용 네이버 JSON — `SearchService#remote_search`로 결과 반환+서버가 `book_meta:<isbn>` 캐시 적재, 무키/실패 시 [](로컬 폴백 없음, 타이핑 autocomplete 와 분리); 인가는 `search?` 재사용). index 는 페이지네이션(PER_PAGE=24)하고 **검색 upsert 캐시(`category: searched`)를 카탈로그에서 제외**해 무한 증가를 막는다(#2, searched 는 로컬 검색 폴백에서만 쓰임).

## 패턴·규칙
- **인가 안전망(fail-closed)**: `ApplicationController` 의 `after_action :verify_authorized` 가 authorize 미호출 액션을 예외로 실패시킨다. 공개·역할게이트·표현용 액션만 각 컨트롤러에서 이유를 달아 `skip_after_action :verify_authorized`(또는 `skip_authorization`)로 제외한다(예: dashboard·shops·sessions·registrations·schools).
- **최상위 = per-action Pundit**: 학생/공용 컨트롤러는 각 액션에서 `authorize`·`policy_scope` 를 직접 호출한다.
- **네임스페이스 = 역할 게이트**: 각 하위 `Base*Controller` 가 `require_*!` before_action 으로 역할을 일괄 검증하고 `verify_authorized` 를 스킵한다(단, `teacher/reviews` 는 예외로 per-action Pundit 사용).
- **세션 게이트**: 로그인·미정지 여부를 매 요청 검사(정지 시 즉시 로그아웃).
