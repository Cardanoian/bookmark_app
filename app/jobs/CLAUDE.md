# app/jobs — 백그라운드 잡 (Solid Queue)

독후감 제출 후 지연이 큰 AI 작업(5축 첨삭·손글씨 OCR)과 온디맨드 게임 콘텐츠 워밍을 비동기로 처리하는 Active Job 계층. Solid Queue 어댑터에서 `:default` 큐로 실행되며, 상태(ai_status·generation_status)를 전이시키고 완료 결과를 Turbo Stream 으로 **비차단** 방송한다. AI 호출은 `app/services/ai` 서비스에 위임한다.

## 파일
- `application_job.rb` — 모든 잡의 베이스 클래스(`ActiveJob::Base`). 현재 커스텀 없음(재시도/discard 훅은 주석 상태).
- `mail_delivery_job.rb` — **메일 발송 잡**(`ActionMailer::MailDeliveryJob` 대체, `ApplicationMailer.delivery_job` 이 지정). **발송 실패의 유일한 관측 지점**이다 — 비밀번호 재설정은 계정 열거를 막으려 존재하지 않는 주소에도 성공 화면을 보여주므로, 로그가 없으면 "메일이 안 오는데 앱 어디에도 흔적이 없는" 진단 불가 상태가 된다. 실패 시 `Mail::ResendGateway.classify` 로 원인을 분류해 `AuditLog` 에 `mail.domain_unverified`(도메인 미검증) 또는 `mail.delivery_failed` 를 남기고, **원문 메시지를 metadata 에 항상 보존**(문자열 매칭이 젬 업데이트로 깨져도 로그로 원인 확인 가능)한다. 수신자 주소는 metadata 에 넣지 않고 `target` 으로 User 를 건다. 쿼터 초과(`Resend::Error::RateLimitExceededError`)만 `retry_on`(polynomially_longer, 5회)으로 재시도하고 **나머지 실패는 삼킨다**(사용자 응답은 이미 반환된 뒤라 재시도로 복구되는 것이 없고, 큐에 실패 더미만 쌓인다).
- `ai_review_job.rb` — 비동기 5축 첨삭. `Ai::ReviewService` 로 루브릭 산출→등급·포인트·향상도 저장, 멱등 델타로 포인트 적립 후 교사 검토 목록에 행 방송(스트림·타깃 이름 `review_queue` 는 방송·구독·테스트가 결합된 내부 식별자라 문구 변경과 무관하게 유지). **완료·실패 모두 `report` 스트림으로 `reports/_report_detail`(target `dom_id(report,:detail)`)을 replace 방송**해 학생 상세(show)의 5축 결과를 새로고침 없이 라이브 갱신한다. **피드백 가시성 게이트(report-review-gate)**: partial이 `feedback_visible?`(`reviewed? && rubric.present?`)로 게이트되어, 미검토 독후감(ai_status done, reviewed false)에는 "선생님 확인 중" 배너만 렌더되고 첨삭 텍스트·등급은 미노출된다 — 학생이 검수 없는 AI 생성물을 바로 보지 않는다(교사 승인까지 비공개). 방송 실패는 rescue 로 흡수하되 **내부 rescue는 커밋된 첨삭 결과를 보존**해, 방송 장애가 리포트 상태를 뒤집지 않는다(ai_status: done 유지). 첨삭 자체 실패 시 `:failed`; 대기 중 독후감이 삭제되어 역직렬화할 수 없으면 작업을 폐기한다.
- `sequel_feedback_job.rb` — **비동기 뒷이야기 격려 AI 코멘트(AiReviewJob 미러, 가벼움)**. `perform(sequel_id)`가 `ai_status`→processing 후 `Ai::SequelFeedbackService`로 코멘트 산출(무키/실패면 규칙기반 폴백이라 **항상 코멘트 확보**), `ai_comment` 저장 + `ai_status`→done, 작성자 play 화면의 그 뒷이야기 AI 코멘트 영역(`dom_id(sequel, :feedback)`)을 **Turbo 방송으로 라이브 교체**(작성자 본인만 구독, `games/sequel/_feedback`). 대기 중 삭제되면 no-op, 예외는 `:failed` 전이. 학생 무대기(백그라운드).
- `ocr_job.rb` — 비동기 손글씨 OCR. **이 폴더에서 유일하게 Gemini(`Ai::GeminiClient`, `gemini-3.5-flash-lite`)를 쓰는 잡**이다(나머지 AI 잡은 Claude — Claude Haiku 의 손글씨 인식 품질이 실사용에 못 미쳐 OCR 경로만 되돌렸다). 따라서 키·게이트·rescue 대상이 모두 Gemini 쪽이다(`Ai::GeminiClient::ApiError`). `Ai::OcrService` 로 사진 blob→텍스트를 `report.body` 초안에 채우고 작성자 에디터(`report_editor` 채널)에 `report_body_field` **와 `#ocr_reading_status`(제출 안내)** 를 방송 교체(2건). **상태 영역을 함께 바꿔야 하는 이유**: 본문만 갈면 "사진에서 글자를 읽고 있어요" 배너가 그대로 남아 글자가 채워졌는데도 화면은 처리 중이라고 말한다 — 학생이 제출하기를 누를 이유를 못 느끼고 떠나면 초안인 채로 남아 첨삭이 영영 안 붙는다(`submitted_at` 경계의 시작점). 성공 방송 마크업은 `reports/edit` 의 done 분기와 1:1로 맞추고, 방송 실패는 rescue 로 흡수해 이미 커밋된 `:done` 을 뒤집지 않는다. 키 없음(`Unavailable`)·API 실패(`ApiError`) 모두 `:failed` 로 전이해 pending 고착을 막고, **실패 시 compose 화면의 `#ocr_reading_status` 상태 영역을 "못 읽었어요 + 다시 찍기" 안내로 방송 교체**해 무한 "읽는 중" 고착을 막는다(방송 자체 실패는 rescue 로 흡수). **AI 동의 게이트(P1-1)**: `perform` 최상단에서 `Ai::ConsentGate.llm_allowed?(report.user, client: gate_client_factory.call)`를 재평가해, "동의 후 사진 업로드 → 교사 철회 → 인플라이트 잡 실행" 레이스에서 미동의 학생의 손글씨 이미지가 Gemini 로 전송되지 않게 조기 `:failed`+실패방송한다(컨트롤러 게이트와 이중). 게이트 클라이언트는 클래스 팩토리 `gate_client_factory`(테스트 seam, `reset_factories!` — GenerateGameContentJob 선례)로 주입 가능.
- `generate_game_content_job.rb` — **온디맨드 게임 콘텐츠 백그라운드 워밍(Phase 2b §2b.2)**. `ContentProvider`가 캐시 MISS 시(또는 오프라인 전용 축의 재시도, 아래 참고) 1건 적재하며, 아동은 이미 오프라인 세트로 플레이 중이라 **비차단 승격**이다. `perform(book_id, band, content_axis)`가 ① dedup 가드(같은 축에 **살아있는**[스테일 아닌] warming 행 또는 이미 **실제 AI 로 게시된**[`quiz_questions.source == :ai`] ready 행이 있으면 조기 반환; `reported: true` 행은 판정에서 제외해 신고 후 재생성이 막히지 않게 함 — **"AI 워밍됨" 판정은 content_version 크기가 아니라 실제 문항 source 로**, 신고 후 재생성된 오프라인 행이나 신고돼 숨겨진 옛 AI 행이 재워밍을 침묵 차단하지 않도록 함) ② 다음 content_version 의 **warming** system Quiz 선점 전 `STALE_WARMING_AFTER`(10분) 넘긴 스테일 warming 행을 리핑(폐기)해 하드크래시로 인한 영구 고착을 막고, 부분 유니크 인덱스로 동시 선점 1건만 성공(나머지 `RecordNotUnique`→포기 = thundering-herd 1생성) ③ `QuizDraftService#content_set` 생성 ④ **`Ai::QuizModerator` 게시 전 검증** ⑤ 통과→quiz_questions 저장(source=ai)+ready 전이(트랜잭션 커밋)+비차단 Turbo 방송("새 문제 준비됐어요", **방송 자체의 실패는 별도 rescue 로 흡수해 이미 커밋된 ready 게시를 되돌리지 않음**); 거부/실패(트랜잭션 실패 등, perform 최상위 rescue 로 전파)→게시 안 함(DB 재확인 후 **실제로 아직 warming 인 경우에만** 폐기, 오프라인 유지)+moderation 거부 카운터. 잡 인자는 직렬화되므로 스텁 클라이언트/모더레이터는 클래스 팩토리(`draft_service_factory`/`moderator_factory`, 테스트 teardown 에서 `reset_factories!`)로 주입한다.
- `book_summary_job.rb` — **비동기 Claude 줄거리 생성(게임 재구성 Phase 4 §1c, BookEnrichmentJob 미러)**. `perform(book_id)`가 AI 퀴즈 워밍이 접지 콘텐츠를 만들 수 있도록 `book.summary` 를 채운다. **멱등**: 이미 summary 있거나 `summary_checked_at` 있으면 skip. **무키 no-op**: `Ai::ClaudeClient.new.configured?` false 면 checked_at 을 세팅하지 않고 즉시 반환(키 생기면 재시도되게 — 영구 무명 마킹 금지). 키 있음: `Ai::BookSummaryService`가 확신 있는 줄거리를 주면 `summary`+`summary_checked_at` 저장, nil(모르는 책)이면 `summary_checked_at` 만 저장(환각 방지·재확인 차단). 아동 대면 아닌 백그라운드라 무대기 불변식 무관·크래시 0. 트리거: `ContentProvider#maybe_enqueue_warming`(온디맨드, 줄거리 미확인 책이면 워밍 예산 하 함께 큐잉) + `games:backfill_book_summaries` rake(벌크).
- `book_enrichment_job.rb` — **비동기 도서 genre 보강**. 공란 `genre`인 `Book` 을 무API `Books::GenreInference`로 추론해 채운다(`SearchService`가 신규 searched 캐시 시 + `Recommendations::Importer`가 XLSX 유입 공란 도서에 대해 커밋 후 enqueue). 멱등(이미 genre 있으면 no-op)·외부 API 0.
- `library/nearby_libraries_warm_job.rb` — **인근 도서관 비동기 워밍**. `Library::NearbyLibrariesWarmJob#perform(book_id, school_id)`가 `NearbyAvailability#warm!` 로 소장목록·대출여부 캐시를 채운 뒤, `[school.id, book.id, :nearby_libraries]` 스트림에 `target: "nearby_libraries"` 로 완성본 파셜을 **replace 방송**해 프레임을 교체한다. 트리거: 렌더 경로(`NearbyAvailability#call`)가 캐시 미스에서 원자 마커를 획득했을 때(반 동시접속도 5분당 1건). **왜 잡으로 빼냐** — 운영 실측 `libSrchByBook` 9.2~9.8초 · `bookExist` 1콜 7.9~35.5초(5곳 순차 101초·동시 8.7초)라 콜드 한 번에 최소 18초가 든다. 요청 안에서 감당할 방법이 없다(예산을 조이면 "확인 필요"만 늘고 늘리면 아이가 그만큼 기다린다). 멱등(캐시 히트면 외부 콜 0)·무키 no-op·삭제된 book/school no-op. **방송 실패는 이미 채운 캐시를 되돌리지 않는다**(별도 rescue, AiReviewJob 선례).
- `library/popular_discovery_warm_job.rb` — **정보나루 학년군 인기도서 풀 비동기 워밍(책 발견 폴백)**. `Library::PopularDiscoveryWarmJob#perform(band)`가 `Library::PopularDiscovery.new.warm(band)`를 호출해 정보나루 top-200 인기대출 ISBN을 기존 카탈로그와 교집합 후 캐시. 멱등(풀 있으면 no-op)·무키 no-op(키 없으면 워밍 건너뜀). 트리거: `PopularDiscovery#pool_book_ids` 워밍 마커 획득 시. 백그라운드 대면 아닌 비차단 안전망.
- `recommendation_cover_enrichment_job.rb` — 공식 추천도서 XLSX 업로드 커밋 후 예약되는 **비동기 표지 보강**. 해당 import의 `cover_url` 공란 도서만 `Books::CatalogEnricher`에 넘겨 네이버 API를 순차 호출하며, 무키·원격 실패는 no-op이고 재업로드 시 재예약되어 자연스럽게 재시도한다.
- `accounts/purge_credentials_job.rb` — **계정 연동 자격증명 야간 purge(account_linking_seasons_plan §Phase 5)**. `Accounts::PurgeCredentialsJob#perform(now:)` — 교사 되돌리기 창(`PURGE_WINDOW`=14일) 경과·**미되돌림(active)** 병합의 `AccountMerge.snapshot` 에서 `password_digest`(old_pre_merge·new_attributes 양쪽)만 nullify 해 삭제된 아동 계정 PII 보존기간을 제한한다(나머지 snapshot=매니페스트·시즌·평생 스냅샷은 보존 → 총괄 구조 reverse 는 여전히 가능). **멱등**(digest 이미 nil 이면 미기록, `update_columns`)·`{scanned:, purged:}` 반환. `now:` 주입으로 창 경계 테스트. `config/recurring.yml`(`at 4am every day`) + `account_links:purge_credentials` rake 공유. **주의**: purge 후 총괄 reverse 는 구조 복원되나 복원 placeholder 는 비번 없어 로그인 불가 → 담임 비번 재설정 필요.
- `missions/reevaluate_job.rb` — **미션 완료·보상 주기 재평가(menu_refactor 심화 §2.A.6 안전망2)**. `Missions::ReevaluateJob` — active + 최근 종료(종료 후 `GRACE_DAYS`=3일 이내) published 미션의 미보상 participation 을 순회하며 `Missions::Rewarder#reward!`(멱등)를 재실행해 이벤트 훅 미스·잡 실패·지연배정 갭을 흡수하는 최종 백스톱. `config/recurring.yml`(production) 에서 매시 실행. **MonsterUnlock self-heal 은 completed_at 을 재생성 못 해 안전망이 아니며**, 이 주기 잡 + AssignmentSync 즉시 평가가 안전망이다. dev/test 는 production 전용이라 즉시 평가 + 수동 `missions:reevaluate` rake 로 커버.
